# SNMP SET: the served ladder and write admission

Moved from CLAUDE.md so the auto-loaded file stays under its size limit. Read this before changing the area it covers.
It covers `snmp_set.go` and the admission gates.

## SET is served on one column (add-snmp-set)

**SNMP SET (add-snmp-set, nl6#684).** `snmp_set.go` serves SetRequest at v1/v2c/v3: ONE curated writable column (`ifAdminStatus.<N>`, reason per row), the RFC 3416 §4.2.5 ladder in RFC order (value tests BEFORE the instance test; wrong arity under the column is `noCreation`), validate-all-then-apply, the request's varbind bytes echoed verbatim, v1 answers via `v1SetErrorStatus` (RFC 3584 §4.3). The PDU tag list is `servedPDUTag` and THREE parsers read it (`extractOIDAndTypeFromScopedPDU`, `extractRequestIDFromScopedPDU`, `parseIncomingRequest`); a hand-written copy in the third is how every SET response carried request-id 123 on the first cut. Values come from `parseVarBinds`, a sibling of `parseVarBindNames`, never a change to it. The apply is `InterfaceState.ApplyAdminStatus`, the funnel every admin mutation takes (REST POST, its auto-revert, SET); since nl6#694 it does NOT cascade. Oper is derived, so a SET of `up(1)` over a down link is read back with `ifOperStatus = 2` and an admin bounce does not repair a simulated cable pull. **BREAKING for REST clients:** the admin-status POST now moves oper and fires link telemetry. `make test-interop` runs `snmpset`/`snmpget`/`snmptrapd` against it. Record in `context/snmp-wire-encoding.md`.

## Write admission is opt-in and both gates ship together (nl6#690)

**SET write admission is OPT-IN, and BOTH gates ship together (nl6#690).** nl6#684 admitted a SET on GET's terms, which was right while every served PDU was a read. **BREAKING: a default fleet now answers NO SET at any version.** `-snmp-write-community` (empty default) / REST `write_community` gates v1/v2c; `-snmp-set-min-security-level none|auth|priv` (default `auth`) / REST `snmpv3.set_min_security_level` gates v3. They cover DISJOINT halves. A v3 message carries no community and a v1/v2c message carries no security level, so shipping one leaves the other version exactly as reported. **The two refusals have DIFFERENT SHAPES and that is not drift**: a v1/v2c community mismatch is DISCARDED (what real hardware does; `snmpset` shows a timeout, so the once-per-device log line is the only thing naming the cause), while a v3 level below the minimum gets the `usmStatsUnsupportedSecLevels` Report RFC 3414 §3.2 step 5 prescribes and the agent already emits for PRIV-to-no-priv. **READS ARE UNTOUCHED at every version** and the asymmetry is deliberate, stated in `docs/reference/snmp.md`. The rule lives ONCE in `snmp_set.go` (`admitSetV2c` / `admitSetV3`) and runs BEFORE any binding is parsed; the user and USM checks run FIRST so a wrong user or digest is reported as itself. `securityLevelUnset` is the ZERO VALUE and resolves to `authNoPriv`: ordering `noAuthNoPriv` at zero would make every `SNMPServer` literal admit an unauthenticated write. `setAdmissionConfig` rides on `ExportSeed` (one plumbing channel, not a twelfth positional parameter) and a nil seed REFUSES. The write community is WRITE-ONLY. It is never echoed by `GET /api/v1/devices`, pinned by an AST scan, because this repo has echoed a credential before. **`CommunityParsed` is defence in depth, not a live fix**: mutation testing showed the unparsed-community case is unreachable today because all three envelope readers agree to stop at a length they cannot honour, so the datagram is discarded as malformed first. It is kept for the day one of them diverges again (nl6#559, nl6#562 each moved one) and asserted on `admitSetV2c` directly. Tests: `snmp_set_admission_test.go` (dispatcher-driven), `snmp_set_admission_config_test.go` (AST scans), `snmp_set_admission_interop_test.go` (net-snmp, every negative row bracketed by a POSITIVE CONTROL on the same listener, because a timeout cannot tell a refusal from a dead socket). Ladder tests are exempt via `allowSetsForTest`, which is greppable for exactly that reason.
