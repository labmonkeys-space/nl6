# The scenario post-window barrier (nl6#500, #567, #618)



Extracted verbatim from `CLAUDE.md`, which exceeded the 150k-char auto-load limit. This is the long-form record: what the defect was, how it was found, and which mistake it is easy to reintroduce. `CLAUDE.md` carries the short invariants and points here.


**The scenario post-window phase is a BARRIER, not a duration (nl6#500).** A scenario submit's `drain` is REJECTED with a 400 — the newest member of the accepted-echoed-ignored family that `-flow-tick-interval`, `-trap-interval` and `-syslog-interval` already document (nl6#445). It never configured anything: `gateState.drainEnd` was written twice and read nowhere, `decide()` compares against `t1` only, and the window self-close timer uses the window alone. At T1 the terminal gate is published so no new fire initiates, and `finish()` then waits for the work ALREADY ADMITTED to return from its write — one write on the syslog/trap paths, one paginated `Tick` batch on the flow paths. Measured on syslog at T1 + 9ms with a 30s drain configured. The refusal keys on the KEY's presence (`json.RawMessage`, so `""`, `null` and a non-string value all 400 with the same actionable message), and it runs BEFORE the window parse so a body with both faults hears about the schema change first. The `drain` ledger bucket and the `drain_end` timestamp stay: both are observed, not configured. **The regression stop is BEHAVIOURAL** (`TestScenarioDrainEnd_IsTheReleaseInstantNotADeadline`: `drain_end` must equal the release instant under synctest) because a reviewer rebuilt the whole knob as `Grace` with a name-scanning test green; the identifier scan is a cheap second net only. **`closeAndWait` IS BOUNDED as of nl6#567**, and the BARRIER is what got bounded, not the transports. It gives up at `drainBarrierTimeout` (60s, PRIMARY not derived: an earlier cut wrote it as `2 * drainWatchdogInterval`, which meant lowering the watchdog to see the log sooner silently shortened the CEILING, to 10s at a 5s watchdog, below the write timeout it must clear; `TestDrainBarrierCeilingClearsItsInputs` asserts the relationships instead) and RETURNS the number of sends still in flight. **nl6#567 BOUNDED THE BARRIER ONLY, AND THAT WAS THE UNCOMMON CASE; nl6#618 BOUNDED FINALIZE.** `finish()` joins the scheduler and the trap and flow tickers BEFORE the barrier, and every one of those was a bare channel receive; the syslog and trap schedulers fire INLINE, so a stalled SCHEDULER-DRIVEN write parked finalize at `c.sched.Stop()` with the ceiling never armed, leaving nl6#567 covering only fires admitted OUTSIDE the scheduler. Found by a test that HUNG FOR FIVE MINUTES with `finish` blocked at `scenario_controller.go:1373`, after two reviewers had flagged only the ticker joins. **All four waits now share ONE budget (`finalizeBudget`), not a ceiling each**: four ceilings would bound finalize at four times the number the operator was told, and the property worth having is a single one. `SyslogScheduler.StopAsync` splits the signal from the wait so the run-loop exit is JOINABLE; `joinWithin` is the shared helper; whatever did not finish is reported as `incomplete_joins`. **NOTHING IS CANCELLED**, so an abandoned join keeps running and can still move counters after the snapshot, the same caveat `drain_stragglers` carries. `FlowExporter.writeOverride` was added for this: the flow join had NO test seam, so no test could park a flow `Tick` write, and that join runs under `c.mu` so it blocked `Phase`/`Result`/`LiveCounts` too. Both mutations are pinned (reverting either join to a bare receive HANGS the suite rather than failing it, which is the defect's own shape). Per-transport write deadlines were the rejected alternative: they cannot bound the total (syslog TCP serialises behind `writeMu`, so a device's worst case is 2s × the fires queued behind it) and they are blind to the case that has no deadline to set at all, namely an admitted fire that never calls `leave()` because its write path panicked or a callback was dropped. **THE STRAGGLERS ARE NOT CANCELLED and cannot be** (nothing interrupts a write parked in the kernel): they keep running and keep moving ledger counters after the snapshot. Those are atomics, so there is no race; what is lost is that `emitted` is incremented at GENERATION and `sent` at the write's RETURN, so a straggler sits between the two and the affected participant's identity may not hold. That is why the count is reported as its OWN field (`drain_stragglers`, `omitempty`, so a healthy report is byte-identical to before) and NEVER folded into `dropped` — a straggler may still reach the collector, so `dropped` would assert an outcome nothing observed. Production never checks the identity (every `identityHolds` call site is a test), so nothing fails on a live simulator. `drainGate` carries an `inflight atomic.Int64` shadowing the WaitGroup, because a `sync.WaitGroup` cannot be read. Three residuals, recorded rather than hidden: a truncated finalize leaves the `wg.Wait()` goroutine parked until its last straggler returns, or forever if one never does (one goroutine, per truncated finalize, on a shutdown path); `emitting` flips false while stragglers may still spend limiter tokens, so a peer starting then sees no contention; and `Shutdown` proceeds to tear down exporters while a straggler is still inside a write. **60s also exceeds `docker stop`'s default 10s grace**, so a containerised deployment may be SIGKILLed before the ceiling fires and write no report at all: raise `stop_grace_period` if a truncated report is worth more than a fast stop. Two races the review caught and the tests now pin: `leave()` does `wg.Done()` BEFORE the shadow decrement (the other order let the last fire read 0 while `done` was not yet closed, so a give-up in that window reported a truncated run as CLEAN), and the ceiling branch prefers a closed `done` because `select` picks at random among ready cases. The count is floored at 1 on the give-up path, which is an invariant and not a fudge: reaching that branch means `done` was not closed, so at least one fire had not called `wg.Done()`.
