# Device-creation batching: how the gate is tested



Extracted verbatim from `CLAUDE.md`, which exceeded the 150k-char auto-load limit. This is the long-form record: what the defect was, how it was found, and which mistake it is easy to reintroduce. `CLAUDE.md` carries the short invariants and points here.


**Testing this needed two production seams, because the first cut's tests had no detection power and its headline claim was false.** Deleting the gate from `CreateDevicesWithOptions` left three of six tests green — two of them pinned a hand-written MIRROR of the gated body, and the third's "gate is free afterwards" assertion is satisfied trivially by a batch that never took it. Worse, the claim that one test caught a release "moved before the walk" was false for the release point that matters: moved to sit after `PreAllocateTunInterfaces` and before the `currentIP` rewind — the nl6#556 boundary — the whole package stayed green, because that test's evidence was `isPreAllocating`, whose lifetime ends before the rewind. The seams: **`geteuid`** (indirects the privilege check, which sits ABOVE the rewind, so an unprivileged process returns before the half of the window this change is about — faked in BOTH directions, so the privilege-rejection path is exercised on a root CI container too instead of skipping) and **`createBatchStageProbe`** (nil in production; lets a test stand at `stageBatchEntered` / `stageAfterReservation` / `stageBeforeIPWalk` inside a REAL batch, ask whether the gate is held, and abort through the ordinary error return so the deferred release still runs). Every test now drives the real `CreateDevicesWithOptions`, and the gate is only ever observed through `tryEnterCreateBatch`, so a test cannot pass by reaching around a wrapper whose gate is gone. `TestGateIsHeldAtEveryStageOfTheBatch` is the pin for the walk claim, `TestGatedBatchesNeverOverlapOnDeviceIPs` for the defect (each of two racing batches must begin its walk at its OWN start address), `TestRefusedBatchTouchesNoCreationState` for (3), `TestCreateBatchGateIsReleasedOnEveryExitPath` for release on freeze / privilege / abort / panic. Verified by mutation at 20/20 detection over 20 runs each: gate deleted from the wrapper; release moved after the reservation but before the rewind; gate moved below the counter stores; release un-deferred; release at the end of the wrapper (panic only); refusal reading the stale counters; sentinel unclassified at the boundary. **Still not covered:** a batch driven to COMPLETION, which needs root and a Linux TUN device — every probe-driven test aborts before the first device is created, so the walk's own loop and `createDevicesParallel` are as untested as they were before.

Pinned by `prealloc_locking_test.go`, which labels each test as a **race-detector pin** (only fails under `-race`: the worker-index, snapshot-accessor and cleanup tests) or a **value pin** (fails on an assertion either way: duplicate names, the torn `(index, IP)` pair, the progress counter, the IP walk). Every concurrency test in it needs a *spinning* counterpart goroutine with a `running` handshake before the code under test is called — a bounded loop of hand-outs finishes during the batch's own log lines and IP precompute, never overlaps the workers, and gives the detector nothing to pair (measured: 3 detections in 40 runs before the reshape, 20 in 20 after).
