## The `-gnmi-catalog` flag and the catalogue load rules

```text
-gnmi-catalog <path>    # [global] JSON gNMI path catalogue; replaces the catalogue of every type that CARRIES one (resources/<type>/gnmi.json); a type without one keeps none, so the override cannot shadow ciena_waveserver5's optical resolver or gate a legacy type's encodings. Catalogues are GENERATED (make gen-gnmi-catalog) for juniper_mx10004 (Juniper/yang) and cisco_asr9902 (YangModels/yang vendor/cisco/xr/2422, only the modules in go/cmd/xr-chassis/yang-modules.txt, which xr-chassis's `make gen-xr-chassis` regenerates with its bindings); the drift test fails on hand edits; CI runs it via `make test-gnmi-drift`, which clones the pinned YANG and sets `NL6_REQUIRE_YANG_CACHE` so a missing cache FAILS, while a plain `go test` without the cache still skips. The juniper_mx10004 `gnmi-bindings.json`, `juniper_mx10004_snmp_chassis.json` and `juniper_mx10004_ssh_chassis.json` are themselves GENERATED by `make gen-junos-chassis` from `go/cmd/junos-chassis` (model plus templates), which then runs `make gen-gnmi-catalog` so the served `gnmi.json` follows; edit those, and `TestCommittedOutputsMatchModel` fails on hand edits. Under `prefix: list-entry` ONE entry is ONE notification: a per-component leaf is a `filter`ed leaf of the entry's subtree (bindings `filters` map), never a second subtree whose entries OVERLAP the first on the same path; load REFUSES same-origin same-path subtrees whose load-resolvable entries (components/neighbors/static) intersect, while same-path subtrees with DISJOINT entries stay legal (the shipped `CPU0:CORE0` static subtree beside the inventory); a same-path pair keyed on `interfaces` at one position loads only when its two filters are disjoint BY CONSTRUCTION (disjoint iftype sets, disjoint name lists, or a name list inside the other's `!name` list) or another key position is disjoint, since the interface set exists only per device (interfaces keys at different positions are refused; an interfaces key on one side only is unchecked) (nl6#765: FPC0 and Routing Engine0 rendered twice and the leaf-set shape test could not see it; `TestMX10004ComponentsOneNotificationPerEntry` counts). Pairs with an `interfaces` key are not checked. `notification.origin_aliases` (nl6#770) maps request origins an operator types (YANG module names, Junos `Native`) onto `origin`/`native_origin`; responses keep the canonical origin unless `notification.aliased_origin_prefix: empty` (nl6#788: then an aliased request gets an empty prefix origin, or its own spelling on an `echo_origin` subtree, while an origin-less or canonical request keeps the canonical one), the generator derives module-name aliases from each subtree's `module` (bindings list only `Native`), Get and Subscribe canonicalise the origin ONCE before dispatch, on paths the catalogue does NOT own, so the legacy resolver behind the catalogue agrees, and a type without aliases still refuses unknown origins. The cisco_asr9902 interface set (front, management and logical ports, VLAN subinterfaces) lives in the xr-chassis model, so ifTable, `show interfaces brief` and gNMI agree (gNMI serves a VLAN subinterface only under its parent's subinterfaces list, as IOS-XR does); its catalogue picks interfaces with an `iftype:<n>,...` filter on the `interfaces` key source (the filter also takes `name:` and `!name:` ifDescr terms, which is how juniper_mx10004 serves `fxp0` from a management subtree keyed `name:fxp0` and keeps it out of the line-card and out-queue subtrees) and enumerates `<parent>.<index>` ifDescr rows with the `subinterfaces` key source, so a parent without VLAN subinterfaces has no subinterface entry (nl6#810, nl6#808).
```

## A handshake is not an Accept (nl6#663)

**A handshake is not an Accept (nl6#663).** `tls_handshake_failures` counted `Accept` errors, and gRPC runs `ServerHandshake` AFTER `Accept` returns. So the counter read 0 for every client transport mismatch while `docs/reference/gnmi.md` told operators to read it as exactly that signal. It is now incremented from `gnmiHandshakeCountingCreds`, a `credentials.TransportCredentials` wrapper, which is **the only point in gRPC's server path that observes a handshake outcome** (a `StatsHandler`'s `ConnBegin`/`ConnEnd` carry no error). The `Accept` bucket survives as `listener_accept_failures` rather than being deleted, because fd exhaustion at 30k listeners is real. **The reported symptom is a listener that accepts TCP and sends nothing**, which reads as "no gRPC service behind the port" and is not. The diagnosis needs a TLS control dial on the SAME listener, which is why `TestGnmiDialinTLSRejectsPlaintextClient` carries one and why `Clone` must preserve the wrapper. The failure log is `sync.Once`-gated **per manager, not per device**: one misconfigured collector fails once per device per retry.

## gNMI dial-out (add-gnmi-dialout)

**gNMI dial-out (telemetry push, `add-gnmi-dialout`):** `gnmi_dialout_transport.go` (`DialoutTransport` seam + `gnmiReverseTransport` over `github.com/aristanetworks/goarista/gnmireverse`, the Arista `gNMIReverse.Publish(stream SubscribeResponse) → Empty` fire-and-forget flavor; also the shared `parseGnmiPath` / `parseDialoutEncoding` helpers) + `gnmi_dialout_exporter.go` (`GnmiDialoutExporter`: per-device `grpc.ClientConn`+`Publish` stream held in `atomic.Pointer`, own dial→publish reconnect loop with 1s→30s capped backoff, SAMPLE ticker + ON_CHANGE `InterfaceState.AddListener` fan-out, bounded send channel with drop-oldest via `pushOrDrop`) + `gnmi_dialout_manager.go` (`StartGnmiDialoutSubsystem` / shutdown-only `StopGnmiDialout`, `startDeviceGnmiDialoutExporter` captured-pointer-under-RLock attach, `buildDialoutCreds`, `gnmiDialoutAggregates` monotonic per-(collector,flavor) counters, `GET /api/v1/gnmi/dialout/status`). **Dial-out reverses the gRPC role, not the data direction**. The device is the client. Payload generation (`pathResolver`→`encodeUpdates`) and state fan-out are reused verbatim from dial-in, so dial-out/dial-in/SNMP/sFlow agree byte-for-byte at the same instant; only transport + pacing are new. Every dial-out notification carries `Notification.Prefix.Target` = device IP (in-band identity, à la Arista `-target_value`; dial-in responses stay prefix-less). **One ClientConn + one stream per device** (NOT a shared pool, because a single Go ClientConn caps at ~100 concurrent HTTP/2 streams); the client dials from inside the device netns with source IP = device IP (reuses the existing veth + FORWARD egress rule). Two-level config: `[seed]` flags (`-gnmi-mode dial-out`, `-gnmi-dialout-*`) for the auto-start batch + a per-device `gnmi_dialout` REST block (`DeviceGnmiDialoutConfig`), enabling a **mixed dial-in/dial-out fleet**. TLS: `tls.enabled=false` → plaintext; else verify against `ca_pem`/system roots (or `insecure_skip_verify` dev toggle), optional `mtls` reuses `sharedTLSCert` as a **client** cert (it cannot verify the collector, hence `ca_pem`). **`ca_pem` is INLINE, never a path**: the block is REST-settable and a path would be an arbitrary-file-read primitive (CodeQL `go/path-injection`, flagged on the syslog twin, missed here only because CodeQL analyses changed code). A path is accepted solely via `-gnmi-dialout-tls-ca`, read once at startup by `loadTLSCAFile`; `tls.ca_file` is now REJECTED with migration guidance rather than ignored. **`certificateBlocksOnly` strips every non-CERTIFICATE block from a bundle at BOTH entry points (CLI load and REST validate), for syslog and dial-out alike**. `AppendCertsFromPEM` returns true as soon as one cert parses and ignores other blocks, so a combined chain+key file would otherwise store the operator's PRIVATE KEY and serve it via `GET /api/v1/devices`, which echoes `gnmi_dialout` unredacted. `ca_pem` is bounded at 64 KiB (`maxCAPEMBytes`), and is parsed at Validate rather than at attach so a bad bundle is a 400 instead of a 201 followed by per-device silence. Drop-on-outage, no buffering; `StopGnmiDialout` is shutdown-only. See `docs/reference/gnmi-dial-out.md`.

## gNMI decimal values (nl6#812)

**gNMI decimal values:** `resolvedUpdate.Value` carries a `gnmiDecimal`, a distinct type and not a pre-formatted string.
JSON_IETF needs an RFC 7951 quoted decimal while PROTO needs `double_val`.
A Go `string` would silently take the `string_val` branch and corrupt an advertised encoding.
Build it ONLY with `newGnmiDecimal(v, digits)`, which rounds ONCE, half-to-even, to `digits` and stores the decimal string.
JSON_IETF is that string, `double_val` its nearest float64, and `decimal_val` its digits without the point, so every encoding serves one reading (nl6#812).
Rounding per encoding disagreed at 14 to 18 digits, because `val*10^digits` and `FormatFloat` round differently there.
A rounded zero is `+0` in every form.
`castGnmiLeafDigits` refuses NaN, infinities and values whose scaled integer overflows int64, because `const:NaN` and `sine:Inf,...` parse; the resolver logs and skips the leaf.
`TestCatalogDecimal64ServedAtDeclaredDigits` pins every decimal64 leaf of every embedded catalogue, and `TestGnmiDecimalFormsAgree` pins the three forms at digits 1 to 18.
At 18 fraction digits `double_val` is lossy, which is inherent to decimal64 in gNMI's PROTO scalar set.
JSON_IETF and `decimal_val` preserve the digits.

## gNMI union leaves (nl6#807)

**gNMI union leaves (nl6#807):** the generator writes a union leaf's member types as `members`, in declaration order, with nested unions flattened and leafref members resolved.
It writes no `members` when a member is a kind the runtime cannot serve, so that leaf stays a string.
It also writes the deduplicated enumeration names as `enum`.
The cast takes the first member that accepts the value, and an integer member accepts only an integral value.
So the ASR 9902 CPU `state/index` sends `ALL` as `string_val` and `0`..`5` as `uint_val`.
Do not paper over a union with a `types` override to `string`: that is how every CPU index went out as a string.
The JSON_IETF fold casts a repeated list key's path value through the subtree's `state/<key>` leaf, never from whichever leaves the request covered.
String-like members ignore YANG pattern and length restrictions.
`TestASR9902ShapeMatchesCapture` requires each class of a union class (`integer|string`) to be served at least once, because admitting one member alone let this pass.
