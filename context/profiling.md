# Continuous profiling (nl6#635)

Moved from CLAUDE.md so the auto-loaded file stays under its size limit. Read this before changing the area it covers.

**Continuous profiling (nl6#635), one gate, off by default.** `profiling.go` + `profiling_api.go` hold the whole feature (two files, three `go.mod` lines: `pyroscope-go` v1.4.2, `godeltaprof` v0.1.12, and `klauspost/compress` as their indirect; deletable in one commit) (pinned to the newest tag with a `go1.27` build file, because `godeltaprof` forks `runtime/pprof` internals and has broken on Go majors; the Go-bump rule is in `docs/ops/profiling.md`). `enabled` is THE gate; `server_address` (flag or POST body) decides whether the SDK PUSHES as well, and pull-only exists because the runtime allows ONE CPU profile at a time, so an Alloy CPU scrape needs the push collector off (a scrape of `/debug/pprof/profile` while the SDK collects is a `500` from `net/http/pprof`, deliberately not masked). The gated `/debug/pprof/` surface (`net/http/pprof` minus `cmdline`, which prints the basic-auth flag, plus `godeltaprof`'s `delta_heap`/`delta_block`/`delta_mutex`; the bare `/debug/pprof` redirects onto it) is mounted on the ROOT router so Alloy's default paths resolve; importing `net/http/pprof` registers on `http.DefaultServeMux` in `init()` and that is inert only because nl6 serves its own `mux.Router`, which `TestProfilingDefaultServeMuxIsNeverServed` pins by AST-scanning every `http.Server` literal, `new(http.Server)`, zero-value variable, nil `Handler` assignment and `ListenAndServe` call, and `TestProfilingOpensNoListenerByConstruction` pins that the two feature files never call anything that opens a socket. The runtime toggle (`profiling_api.go`, `GET`/`POST /api/v1/profiling`) copies `fidelity_api.go` (pointer bool, one superseding timer, `gen` counter, chain-aware restore of the whole (gate, address) pair reported as `revert_to` + `revert_to_address`, GET reports value in force AND startup flag). **TWO LOCKS, and the order is `profilingLifecycle` -> `profiling.mu`, never the reverse:** **`Profiler.Stop` does NOT flush** (session.Stop takes the stopCh path and uploads nothing; Remote.Stop closes `done` and may drop a queued job), so the stop closure calls `Flush(true)` THEN `Stop()`, in a goroutine waited on for `profilingFlushBound` (2 x the 10 s upload timeout) and abandoned with a log line past that. It runs AFTER `profiling.mu` is released and under `profilingLifecycle`, which serialises every mutation so a concurrent start cannot race a stop; GET takes `profiling.mu` only and never waits behind a dead collector. `Shutdown` calls `stopProfiling()` AFTER `abortActiveScenario()`. **`pushing:true` means the SDK is RUNNING, nothing more:** `pyroscope.Start` never touches the network, so a down/401/wrong-tenant collector surfaces through the SDK's `Logger.Errorf` on its upload goroutines, which `profilerLogger` counts into `sdk_errors` (every error the SDK reports: failed upload, refused CPU collector, full queue), keeps as `last_error`, and logs ONCE per push (`logFirstEncodeErr` convention); the logger is lock-free because the one SDK call made under `profiling.mu` is Start. **Credentials are FLAG-ONLY, REQUIRE THE FLAG, AND ARE BOUND TO THE FLAG'S ADDRESS** (`profilingCredentialsFor`, compared through `normaliseProfilingAddress`: scheme and host lower-cased, trailing slash trimmed): `-profiling-pyroscope-basic-auth` (`parseProfilingBasicAuth`, both halves required, the SDK sends nothing when either is empty) and `-profiling-pyroscope-tenant` are fatal without `-profiling-pyroscope` (they would be withheld from every push forever) and go only to a push whose address equals the flag's; a REST `server_address` that differs gets none and the log says `credentials withheld`, since otherwise an unauthenticated POST redirects heap profiles plus the operator's Basic auth anywhere. An address embedding userinfo, a query or a fragment is refused (echoed, or mangled by the SDK's `/ingest` append), `server_address` on `enabled:false` is a 400 (validated-then-ignored, nl6#445), and `PYROSCOPE_ADHOC_SERVER_ADDRESS`, which the SDK would honour over the flag silently, is refused at startup ONLY when the flag is set and otherwise at the start of a runtime push (500 + `last_error`), so a process that never profiles is not stopped by an unrelated tool's environment. **`server_address` is a `*string` with three shapes:** omitted keeps the address in force if pushing (a bare timed on keeps a REST push), else the flag's, else pull-only; explicit `""` is pull-only even with the flag set (the only way to reach it once a flag was given); a value re-targets. `pyroscopeStart` is a seam (the `writeOverride` pattern) so tests can drive a Start failure and a 1 s `UploadRate`. **Labels are paid unconditionally**: `subsystem=<snmp|trap|syslog|flow|gnmi|gnmi-dialout|scenario>` set once at goroutine birth (`labelSubsystem`, which reuses one prebuilt context per subsystem and RETURNS it: SNMP read loop, trap INFORM reader/retry loops, syslog TCP reconnect loop, dial-out `run`, the fleet flow ticker, the scenario flow ticker) or via `pprof.Do` at the funnel (`withSubsystem`: trap/syslog `fireWithSource`, `tickFlowExporter`, gNMI `Get`/`Subscribe`, scenario `startLocked`/`finish`), each as a `fooLabelled` body wrap, never per datagram. **THE NESTING RULE:** `pprof.Do` restores the labels of the context it was GIVEN, so a funnel called with `context.Background()` from a goroutine with a birth label ERASES that label on the way out; `tickFlowExporter` therefore takes the caller's context and both tickers pass their birth context (`TestProfilingLabel_BirthLabelSurvivesAFunnel`, with the erasure as its control), and `withSubsystem` SKIPS the `pprof.Do` when the context already carries that label, so the fleet ticker allocates no label map per exporter per tick (`TestProfilingWithSubsystemSkipsARedundantRelabel`, AllocsPerRun == 0). An INHERITED label (the scenario scheduler spawned under `startLocked`) does not survive a trap/syslog funnel, by design. Pinned BEHAVIOURALLY by `TestProfilingLabel_*` (goroutine profile or a read from inside the funnel): SNMP read loop, trap fire funnel, trap INFORM loops, syslog fire funnel, flow tick funnel, fleet flow ticker, gNMI Get/Subscribe, dial-out loop, the scenario ticker (between ticks, after ticks ran), scenario `finish`, and a SCHEDULED start's inherited label (read on the scheduler's stop-watch goroutine `Run.func1`, since the scheduler's own loop loses the inherited label at its first fire, by design, and that is asserted too). NOT pinned behaviourally: the syslog TCP reconnect loop and the non-scheduled `startLocked` path; the interop test proves only that a label set through the helper reaches Pyroscope and is filterable, over push AND Alloy scrape (pprof labels are sample labels, so they survive a scrape; measured, row 2). **Mutex/block rates are NOT set** (`TestProfilingRuntimeGlobalsStayZero` pins 0 across a cycle). **The `-profiling-force-gc` default is a MEASUREMENT** (`profiling_gc_bench_test.go`, rule pre-registered in the spec, figures and follow-ups in `docs/ops/profiling.md`; an in-process TUN-free proxy, fleet-scale VM run in that page's Follow-ups). **The check with detection power is `make test-interop-pyroscope`** (CI gate; real `grafana/pyroscope` + `grafana/alloy` containers on the host network, three rows: push with CPU + `alloc_space` + filterable label, Alloy default scrape with CPU + goroutine + the label through the scrape, and a CONTROL service that must return nothing; render errors are retried, not fatal, so a transient 503 cannot fail the gate). Pyroscope 2 holds `/ready` at 503 for ~60 s after start and its legacy `/pyroscope/label-values` needs a `name` it no longer reads from the query string, so the test lists profile types through the Connect `QuerierService/LabelValues` API. The image pins live ONLY in `examples/pyroscope/compose.yml` as literal `image:` lines (Dependabot's docker-compose parser skips the `${VAR:-...}` form); the Makefile reads them from there with `sed`. The compose example carries NO Pyroscope healthcheck (the image has no shell, wget or curl) and nl6 depends on it `service_started`; `run.sh` is the verification. **BREAKING:** the two hand-rolled heap and CPU handlers under `/api/v1/debug/` are GONE (a `git grep` for their old names must return nothing); the replacements are `/debug/pprof/heap` and `/debug/pprof/profile?seconds=N` behind the gate, the console buttons fetch those and surface the 503 body (and net/http/pprof's text/plain 500, `app_api.test.js`). One out-of-wrap edit rode along: `SNMPServer.running` became an `atomic.Bool`, because the first test to drive `Start` and `Stop` on the read loop reported the pre-existing plain-bool race.

## Why force-gc defaults to true

Before each heap snapshot the Pyroscope SDK forces a `runtime.GC()` if no collection ran during the upload interval, so the heap profile is fresh.
`-profiling-force-gc` controls it (`false` sets the SDK's `DisableGCRuns`).
Its default was set from a measurement by a rule registered before the number was known.
The rule: if one `runtime.GC()` on a heap built from N=5000 TUN-less devices, extrapolated linearly to 30,000, exceeds 150 ms (1% of one core per 15 s upload window), the default is `false`; otherwise it is `true`.
`BenchmarkForcedGCOnFleetHeap` (`profiling_gc_bench_test.go`, run with `-run '^$' -bench BenchmarkForcedGCOnFleetHeap -benchtime=5x`) measured 1.0, 1.0 and 1.5 ms at N=1000 (16.7 MiB live heap) and 4.3, 4.8 and 5.8 ms at N=5000 (78.5 MiB).
Linear from the N=5000 median (4.8 ms) that is about 29 ms at 30,000 devices, and about 35 ms from the worst run.
Machine: Apple M1 Max, darwin/arm64, Go 1.27.0, `asr9k` profile.
That is under the 150 ms line by a factor of five, so the default is `true` (the SDK default), and `simulator.go`'s flag default reads from the same constant.
The benchmark is an in-process proxy.
Its devices carry their value engines and resource pointers but no sockets, TUN interfaces or namespace, so a real 30,000-device fleet's heap is larger and its GC slower.
The fleet-scale measurement is still open.
If it crosses the 150 ms line, flip the constant and the table in `docs/ops/profiling.md` together.
