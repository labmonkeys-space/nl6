# Interface state engine: derived oper, subinterfaces, the scenario seed, auto-revert

Moved from CLAUDE.md so the auto-loaded file stays under its size limit. Read this before changing the area it covers.
`context/if-counters.md` holds the counter side (dials, hold, roll-up, clock).

## The state engine (add-interface-state, nl6#694)

**Interface state engine (`interface_state.go`, added by add-interface-state):** `IfCounterCycler` owns an `InterfaceState` per device that stores **link state** / `admin-status` / `last-change` per ifIndex in a packed `atomic.Uint64` slot (3 bits + 3 bits + 58 bits wall-relative ns). **`oper-status` is DERIVED, never stored (nl6#694):** `deriveOper(admin, link)` is the single place RFC 2863's rule is written, and the rule is ASYMMETRIC. `admin down(2)`/`testing(3)` FORCE oper, `admin up(1)` RELEASES it to the link. The three bits that held oper hold link; `_layoutGuard` and the 58-bit `lastChange` are untouched, because a fourth field would cost ~8 years of `lastChange` AND create a second source of truth for a pure function of the other two. `ifAdminStatus.<N>` (`.7`), `ifOperStatus.<N>` (`.8`), `ifLastChange.<N>` (`.9`) are now claimed by the cycler. `GetDynamicAt` reads them from the state engine, so SNMP and gNMI agree byte-for-byte at the same instant. Mutators are `SetLinkState` and the `ApplyAdminStatus` funnel (`SetAdminStatus` is unexported as `setAdminLeaf`, so the funnel is the only admin door). **`SetLinkState` returns a THREE-way `LinkMutation`** (`LinkUnchanged` / `LinkMovedMasked` / `LinkMovedVisible`) because the `bool` it replaced conflated "already at target" with "suppressed", which is why the flap scheduler's no-op log named two causes and one of them described a guard that did not exist. **`ApplyAdminStatus` applies ONE CAS and no longer cascades**: it writes admin and reports the derived oper transition the write implies, so admin-up over a down link returns ONE event and does not raise oper. **`lastChange`, `Broadcast` and the Tier C notify hook all key on the DERIVED transition**, so a masked link move stamps nothing and fires nothing; `Broadcast` also drops a zero-`Changed` event rather than fanning out an update for ifIndex 0. Sources: the flap scheduler (`flap_scheduler.go`, single shared min-heap goroutine driving Poisson-distributed flaps per (device, ifIndex), the same shape as `trap_scheduler.go`) and the REST `oper-status` POST both move the LINK; the REST `admin-status` POST, its auto-revert and SNMP SET of `ifAdminStatus.<N>` (`snmp_set.go`) move admin through the funnel. **The scheduler needs no admin guard**: an admin-down interface is protected by the derivation, so a masked flap moves real state that surfaces when the port is unshut, and is deliberately NOT logged (at `aggressive` on a shut fleet that is ~30k lines/minute describing the feature working). **`POST .../oper-status` is BREAKING**: it sets the link, answers 202 with `{link, oper_status, admin_status, masked}`, and its effect is masked (not refused, because 409 would make the contract depend on another leaf) under admin-down. **Its auto-revert MUST snapshot `Snapshot().Link`**, never the derived oper, or a masked POST's revert writes the mask into the link. State transitions broadcast a `StateChange` event to every registered ON_CHANGE Subscribe listener via a per-stream depth-16 channel with drop-oldest on overflow. Cross-protocol consistency in Tier B: SNMP, gNMI Get, and gNMI Subscribe ON_CHANGE all see the same value at the same instant. **Tier C (`correlate-state-notifications`):** an oper-status transition now also fires correlated link traps + syslog for that ifIndex. `InterfaceState.SetNotify` installs an `atomic.Pointer[func(StateChange)]` hook invoked (oper-only, gated on `LeafOperStatus`) at the end of `Broadcast`, after the slot store commits. The manager wires it at trap/syslog attach time (`wireStateNotify`) to call `FireForInterface(entry, ifIndex)` on the role-matched catalog entries (`EntriesByRole`, vendor-wins-per-role); the closure snapshots the exporters under `device.mu.RLock` and fires outside the lock (closing-guard handles teardown). Covers all three mutation sources (REST, flap scheduler, REST auto-revert) via the single `Broadcast` funnel. Link telemetry volume now rides real state changes (`-if-flap-scenario` / REST), and state-driven fires bypass the Poisson global cap on initial transmit. **Counter hold (`if_counter_hold.go`):** every dial-derived column holds while the DERIVED oper is not `up(1)`, through a per-slot immutable ledger applied at the ONE `heldDeltasAt` read in `GetDynamicAt`, driven by an engine hook on `Broadcast` that reconciles against current state, with a seqlock and two instant clamps that are what keep polls monotonic; record in `context/if-counters.md`. **Counter roll-up (`if_counter_rollup.go`):** a child (one lower layer) serves a hashed share of its parent's SERVED delta and an aggregate (two or more `ifStackTable` lower layers, from `readStackLayers`) the sum of its members', composed inside the same bracket, with the child's packet profile and bases inherited so the bound is exact per column; xr-chassis `bundle_members` renders the stack rows.

## Subinterfaces follow their parent (nl6#842, nl6#843)

**Subinterfaces follow their parent (nl6#842, nl6#843).** `splitSubinterfaceName` (`interface_hierarchy.go`) is the ONE `<parent>.<canonical uint32>` rule; the catalogue's `subinterfaces` key source, the engine's parent table (`setParents`, built in `InitIfCountersWithScenario` before publish, immutable, one level) and the legacy resolver all use it. `deriveChildOper` wraps `deriveOper`: a child that would be up reads `lowerLayerDown(7)` while its parent is not up, and its own forced state wins. A parent's visible transition CAS-stamps each moved child's `lastChange` and returns its event after the parent's, so **`SetLinkState` returns `(LinkMutation, []StateChange)`** and every caller broadcasts all of them; that is what gives the unit its ON_CHANGE update from every mutation source. `linkRoleFor` fires no trap for `up(1)`↔`lowerLayerDown(7)` (RFC 2863 keys both traps on `down(2)`), so a port bounce sends its unit no unpaired `linkUp`; events carry `PrevOper` for that. **Mutations inside a family hold `familyMu`**: a child's oper reads its parent's slot, so per-slot CAS let a stale cascade stamp a child with an OLDER parent transition (`ifLastChange` backwards) and let a child move derive from a parent that changed before its CAS. Interfaces outside a family never take the lock. The child's stored link/admin are never written. A second parent source is `ifStackTable` (`stackedParents`, `ifStackStatus.<higher>.<lower>` = `active(1)`), used only where the name rule gives none: that is how Nokia's router interface `toWAN` follows `port 1/1/1`. **gNMI hides only `NamedSubinterface`s** (name-rule children, served under their port's `subinterfaces`); a stacked child stays an interface there. The stack is cached per `*DeviceResources` and hierarchy warnings log once per process, since the hierarchy is rebuilt per device. `FlapScheduler.Register` skips `Linkless` interfaces: children and `softwareLoopback(24)`. The legacy `pathResolver` skips children on `*`, answers `NotFound` for a child name, and drops child events in `changedUpdatesForPath`, which is why dial-out (legacy resolver only) now lists what dial-in lists.

## `-if-scenario` is a seed with no read-time override (nl6#692)

**`-if-scenario` is a SEED, and there is no read-time override (nl6#692).** `scenarioSeed` (`if_state.go`) overlays the scenario on the JSON `.7`/`.8` rows inside `InitIfCountersWithScenario`'s seed loop, once per device, through `Seed`, NOT through the mutators, which stamp `lastChange` and broadcast, so applying it that way would make a fleet report a transition per interface at boot and fire Tier C link telemetry for state that never changed. **Scenario 1 seeds admin ONLY and PRESERVES the link (nl6#694)**. It had to write oper as well while a cascade existed; under derivation the forcing lives in the accessor, and writing the link down too would model 30,000 severed cables rather than 30,000 shut ports, so unshutting a port would leave it dead. **The issue reported the inverse of the defect and the probe is what caught it**: `findResponse` asked the cycler BEFORE `getIfStateOverride`, and the cycler has served `.7`/`.8`/`.9` from the engine since v0.8.0, so the override was dead on every engine-backed device and was never wired into GETNEXT/GETBULK at all. The flag had done nothing for 22 releases while `cli-flags.md` documented four working scenarios. Re-adding a read-time override is the regression to refuse: it shadows a SET and a REST POST, which is what nl6#692 was filed for, and re-splits GET from the walk. The flag is now validated at startup (`IfStateConfig.validate`), fatal after `-help`/`-version`. Scenario 2 is the identity, so the default fleet's wire output is unchanged EXCEPT at the 18 `cisco_nexus_9500` interfaces (ifIndex 33-40, 51-60) whose JSON ships `ifAdminStatus = 2` with `ifOperStatus = 1`; the derivation serves those `2`. **The rows are NOT edited**: read as a link seed, `ifOperStatus = 1` on a shut port means the cable is good. Measured by `TestShippedServedStateDigest` + `TestServedStateDigestMovedOnlyAtTheNexusRows` (`if_served_state_digest_test.go`), which nl6#694 had to BUILD, because `shippedTagDigest` / `shippedOIDEncodingDigest` read resource files, not served values, so neither could witness a change to `.7`/`.8`/`.9` and nl6#693's "byte-identical" acceptance line named a measurement nothing implemented.

## REST auto-revert convention

**REST auto-revert convention.** `POST .../oper-status` and `POST .../admin-status` accept an optional `duration` field (`{"status":"DOWN","duration":"30s"}`). When set: (1) the handler snapshots the pre-mutation slot value at POST time; (2) `SimulatorManager.revertTimers` registers the timer keyed by `(ip, ifIndex, isOper)` so a subsequent duration POST on the same leaf cancels the first; (3) `device.Stop()` cancels per-device timers, `manager.Shutdown()` cancels all; (4) `duration` is capped at 24h (`maxRevertAfter`), and over-cap returns 400; (5) on-demand HTTP fires bypass the flap scheduler's `-if-flap-global-cap` rate limiter, matching the trap/syslog convention for test-harness use.
