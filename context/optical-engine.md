## gNMI optical serving (`/components` branch)

**gNMI optical serving (`/components` branch):** `Resolve` and `ClassifyLeaves` dispatch on `elems[0]`. `interfaces` selects the packet surface and `components` the optical one, with everything under the single prefix `/components/component[name=$och]/optical-channel/` (`optical-channel` augments `/components/component`, so one branch suffices). `gnmiOpticalLeaves` is the served contract, classified by container shape: `opticalLeafScalar` (in **both** `config/` and `state/`), `opticalLeafStats` (`state/<leaf>/{instant,avg,min,max}`), `opticalLeafCounter` (`fec-uncorrectable-blocks`, a **bare** leaf; asking for `/instant` on it returns a `NotFound` that says why, because that is the mistake a collector author makes by analogy). Values come from `OpticalCycler.GetDynamicAt`, keyed by **component name**, with one elapsed offset per response taken from the optical engine's own `StartTime()`. `config/` and `state/` return the same value for the four scalars, because a simulator's configured intent cannot diverge from its operational state. **Three invariants worth not breaking:** (1) the `ifCounters`/`Unavailable` guard lives INSIDE the interfaces branch. Hoisted, it asserted the *interface* engine for optical paths, so an optical Get on a device with no HC counters failed with a misleading "interface counters not initialized"; (2) optical absence is `NotFound` on a packet device (permanent) but `Unavailable` on an optical type mid-initialisation (retryable). `IsOpticalDeviceType` decides, and conflating them tells a client to poll forever for a surface the device cannot have; (3) `ClassifyLeaves` reads no value engine at all, which is what keeps ON_CHANGE rejection cheap and unable to return `Unavailable`. ON_CHANGE on an optical path is rejected `InvalidArgument` with a **leaf-class-branched** message (`isOpticalLeafSelector`), because the counter wording would tell an operator that `osnr` is a counter. `Capabilities` advertises `openconfig-terminal-device` 2026-01-14, `openconfig-platform` 2025-07-15 and `openconfig-platform-transceiver` 2026-03-25 (the last is **not** decoration: `optical-channel/state` reuses its `optical-power-state` grouping for input/output power and laser bias). `post-fec-ber` is **not** served though OpenConfig defines it. Ciena removed it, so a rule keyed on it would never fire against real hardware; `TestOpticalPathManifest` asserts its absence so "completing the model" requires editing a test that explains why. That test also pins served == manifest in both directions, catching an invented or dropped path in CI; it does **not** prove manifest == YANG (the table was traced by hand against the pinned revisions, and a ygot check would need them vendored).

## Optical value engine (`optical_cycler.go`)

**Optical value engine (`optical_cycler.go`):** `OpticalCycler.GetDynamicAt(component, leaf, t)` is the single dispatcher for every coherent-optical leaf, keyed by **OCH component name** (never `ifIndex`). Same contract as `IfCounterCycler`: pure function of elapsed time, no per-channel goroutine, immutable after publish, single-init panic guard, per-channel jitter over a **sorted** channel slice (seed salt `^0x4F43_0000`). **Two independent dials** (received power `pIn` and accumulated noise `nAse`, with `osnr = pIn − nAse` in dB) because a single power dial makes OSNR perfectly correlated with power and leaves the *attenuation* (low power / normal OSNR) and *ASE* (normal power / low OSNR) quadrants unreachable. Cascade: `osnr → q-value → pre-fec-ber` (`½·erfc`, monotonic. The erfc tail is **shallow** at the 2e-2 SD-FEC threshold, ~3× per 2 dB, so decade-scale assertions there are wrong physics) `→ fec-uncorrectable-blocks`. Off-spine leaves (`output-power`, `target-output-power`, `laser-bias-current`, `chromatic-dispersion`, `polarization-mode-dispersion`, `polarization-dependent-loss`, `frequency`, `operational-mode`, `line-port`) read none of the receive dials. That flatness *is* the fibre-vs-transponder diagnostic. Both dials share a period so their difference collapses exactly to one sinusoid, making the above-threshold integral behind the block counter closed-form, O(1) and monotonic by construction. Types come from the **pinned OpenConfig revision** (terminal-device 2026-01-14 + platform-transceiver 2026-03-25), which governs over Ciena's native model: statistics leaves at `fraction-digits 2`, `pre-fec-ber` at `fraction-digits 18`, `fec-uncorrectable-blocks` a bare `uint64` counter with **no** stats container. **`post-fec-ber` is not served**. OpenConfig defines it but Ciena removed it, so a collector rule keyed on it would never fire against real hardware. `-optical-scenario` / per-device `optical_scenario` selects the health band via `opticalBandFor`; only `failing` crosses the FEC threshold. **Band boundaries are sized against the jitter envelope, not the nominal point:** each dial mean is jittered ±`opticalMeanJitterDB`, so the OSNR mean, their *difference*, spreads over ±2× that, stacked on top of the OSNR sine amplitude (≤ `1.1×(pInAmp+nAseAmp)` in antiphase). The tier contracts (`degraded` never accrues uncorrectable blocks, `failing` always does) must hold for every channel of every seed, so changing any mean, amplitude, or the jitter constant invalidates the arithmetic documented at `opticalBandFor`. `TestOpticalBandContractsHoldAcrossSeeds` sweeps seeds because a single-seed test passes while a fleet-sized share of channels violates the contract. **Capability symmetry with flow:** a non-clean `optical_scenario` on a type with no OCH inventory is rejected **400** (`opticalIncapableRequest`, the inverse mirror of `flowIncapableRequest`), and `opticalScenarioFieldFor` omits the field from `GET /api/v1/devices` for non-optical types rather than reporting a knob that does nothing.

## On-demand optical degradation (`optical_degrade.go`, `optical_api.go`)

**On-demand optical degradation (`optical_degrade.go`, `optical_api.go`):** `POST /api/v1/devices/{ip}/optical/{component}/degrade` with `input_power_drop_db` / `noise_rise_db` / optional `duration` (24h cap; neither offset = clear). Two knobs, not one severity dial. They select the diagnostic quadrant (attenuation: power down, **OSNR unchanged**. The sag hits `pInAt` AND `nAseAt`, because signal and accumulated ASE traverse the same fibre, so it cancels out of `osnr = pIn − nAse`; ASE: power held, OSNR down). Crossing the FEC threshold therefore requires `noise_rise_db`, which is the discrimination collector rules key on and the reason the engine has two dials. **Degradation is an append-only list of immutable `opticalEpisode`s** (`atomic.Pointer[[]opticalEpisode]` per channel, copy-on-append), NOT an install-and-clear pointer: `fec-uncorrectable-blocks` is the time integral of an above-threshold indicator over `[0,t]`, so clearing a "current sag" would remove already-elapsed degradation from the integral and make the counter **decrease**. A collector reads that as a device reboot. Two load-bearing invariants: a published episode's window is frozen (past segments can never change → monotonic by construction), and `t0` is never in the past (no already-observable value is rewritten; a backdated request clamps forward). The one permitted mutation is truncating an *open* episode's end forward to `now` when a later POST supersedes it. `aboveThresholdSeconds` is therefore **piecewise**: the OSNR mean steps at episode boundaries, so the interval splits there and the same closed-form arcsine applies per segment (cost O(boundaries), not O(t); an undegraded channel takes the original single-segment path). The sag is applied in `pInAt`, `nAseAt` **and `osnrAt`**, because `osnrAt` reads the precomputed phasor, so sagging `pInAt` alone would move the input-power leaf while leaving the whole cascade untouched. **No revert timer** (deviation from the story's letter, contract preserved): an episode carries its own end and the engine is a pure function of `t`, so the revert is arithmetic. There is nothing to schedule, cancel, or leak, unlike the interface-state convention, which must put mutated state back.
