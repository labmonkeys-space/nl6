Syslog export

nl6 emits syslog messages in either RFC 5424 (modern, structured) or RFC 3164 (legacy BSD) format, over UDP, TCP (RFC 6587) or TLS (RFC 5425). Format and transport are per device. For enabling the feature, CLI flags, and troubleshooting see Syslog export how-to and CLI flags → UDP syslog export.

Architecture​

  • One central scheduler fires every device at Poisson-drawn times, the same design as trap export.
  • Each device owns its transport and stats. SysName, Model, Serial and ChassisID are captured when the device's exporter is built and stay stable for the device's lifetime.
  • Each fire produces one message, sent as one datagram or one framed stream record.
  • The universal catalog is compiled in from resources/_common/syslog.json. -syslog-catalog <path> replaces the entire catalog surface (universal + per-type overlays) with a single JSON file.
  • Per-type catalog overlays load from resources/<slug>/syslog.json when present. Each device of type <slug> fires from the merged catalog (universal + per-type). See Per-type catalog overlays.
  • The global rate limiter (-syslog-global-cap) gates scheduled fires. On-demand fires via the HTTP endpoint bypass the cap. They're for fault injection, not load shaping.

Scope​

UDP is the default transport. TCP (RFC 6587) and TLS (RFC 5425) are documented under TCP transport below. A TCP or TLS device owns one connection and has no shared-socket fallback.

All header tokens pass through sanitisation per RFC 5424 §6: spaces become hyphens, non-ASCII bytes become _, lengths are capped. The dry-render check at catalog load rejects any entry whose worst-case expansion exceeds 1400 bytes.

Structured-data grammar​

Each key in the catalog's structuredData map becomes one SD-PARAM inside a single [meta@32473 ...] element. The SD-ID is the constant meta@32473 (RFC 5612's documentation PEN), not the entry's appName. Keys must match the RFC 5424 §6.3.3 SD-NAME grammar (PRINTUSASCII, no space / = / ] / ", 1..32 chars). Values are rendered through the standard template vocabulary. SD-PARAM value escapes (" → \", \ → \\, ] → \]) are applied automatically.

RFC 3164 has no structured-data support; the catalog's structuredData and msgId fields are silently dropped for this format. If a catalog entry depends on structured data for correlation, stay on 5424.

PRI calculation​

Per RFC 5424 §6.2.1 (shared by both formats):

PRI = facility * 8 + severity

Range 0..191. No leading zeros on the wire.

HOSTNAME derivation​

Resolved at fire time, in priority order:

  1. Catalog hostname template. If the entry defines a non-empty hostname field, render it through the template vocabulary and use the result.
  2. Device's sysName.0. Captured at device construction from the SNMP OID table. Used when the catalog entry has no hostname template and the device's sysName is non-empty.
  3. Device's IPv4. Dotted-quad fallback when sysName is also empty.

Whatever branch fires, the result is passed through hostname sanitisation: spaces → hyphens (mandated by both RFCs), non-ASCII and control chars → _.

Catalog JSON schema​

The embedded universal catalog at go/nl6/resources/_common/syslog.json is the authoritative example:

{
  "entries": [
    {
      "name": "interface-down",
      "weight": 40,
      "facility": "local7",
      "severity": "error",
      "appName": "IFMGR",
      "msgId": "LINKDOWN",
      "structuredData": {
        "ifIndex": "{{.IfIndex}}",
        "ifName": "{{.IfName}}"
      },
      "template": "Interface {{.IfName}} (ifIndex={{.IfIndex}}) changed state to down"
    }
  ]
}

Ships six generic entries matching common network-device semantics:

Weights sum to 135, but interface-up and interface-down are role-tagged and never fire from the scheduler. They fire on an interface oper-status transition: a flap scenario (-if-flap-scenario), a REST oper-status or admin-status POST, or an SNMP SET of ifAdminStatus. The scheduler draws from the four untagged entries only, so the scheduled weight is 55.

Template vocabulary​

Both the template body, hostname override, and every value in structuredData are evaluated as Go text/template strings per fire. The vocabulary is unified with the trap subsystem. The same twelve fields work on both sides:

FieldEvaluation
{{.IfIndex}}Random ifIndex drawn from the device's simulated interface set at fire time
{{.IfName}}ifDescr.<IfIndex> live lookup from the device's SNMP OID table; falls back to synthesised GigabitEthernet0/<N> on miss
{{.Uptime}}Device uptime in 1/100-second ticks
{{.Now}}Unix epoch seconds
{{.DeviceIP}}Dotted-quad IPv4 of the device
{{.SysName}}Device's sysName.0 value (captured at construction)
{{.Model}}Human-readable model string derived from device-type slug (e.g., cisco_ios → Cisco IOS)
{{.Serial}}Deterministic SN + 8-hex-digit serial synthesised from the device's IPv4
{{.ChassisID}}Deterministic locally-administered MAC-style chassis ID synthesised from the device's IPv4 (02:42:xx:xx:xx:xx)
{{.NowLocal}}Fire time as local 2006-01-02 15:04:05
{{.Detail}}Per-fire free-form measurement suffix. Empty unless the firing site supplies it (the optical alarms carry the triggering OSNR this way)
{{.IfAdminStatus}}Admin status of IfIndex read from the interface state engine at fire time. Syslog spells it up(1) or down(2) as an SNMP display renders ifAdminStatus; a trap renders the IF-MIB integer 1 or 2 so it can fill a typed ifAdminStatus varbind. A state-driven link fire carries the admin value of its event. Up on a device without an engine

References to any other field are rejected at catalog load. Class 2 random-per-fire fields (PeerIP, User, SourceIP, RuleName, NeighborRouterID) are explicitly unsupported. Syslog entries that semantically require them (sshd auth, BGP/OSPF events, firewall rules) are shipped bland or not at all.

Per-type catalog overlays​

Devices can ship vendor-flavoured syslog content via per-type JSON files at resources/<slug>/syslog.json. When a per-type file exists, the simulator merges it with the universal catalog using name-based overlay semantics:

  1. Entries whose names are unique to the per-type file are added.
  2. Entries whose names match a universal entry override the universal entry for devices of that type.
  3. Universal entries with no matching per-type name carry through.

Set "extends": false at the top of the per-type file for a pure replacement (no universal entries carry through for that type). The default is "extends": true.

Their realistic content depends on Class 2 random fields, which are not supported.

Starting syslog export​

Starting export, per-device source IPs and TCP or TLS collector setup are covered in the syslog export how-to. The per-device syslog block of POST /api/v1/devices is in Web API → Per-device export blocks.

TCP transport (RFC 6587)​

Syslog is UDP by default. Setting -syslog-transport tcp, or a per-device "transport": "tcp", carries the same messages over a per-device TCP connection instead. The message bytes do not change; only the framing differs.

Framing​

framingshapewhen
octet-counting (default)<byteCount> SP <msg>RFC 6587 §3.4.1. What rsyslog emits, and unambiguous for any payload.
non-transparent<msg> LFRFC 6587 §3.4.2. Some Cisco platforms speak only this.

Setting framing while the transport is udp is rejected, not ignored. The CLI equivalent, -syslog-framing, seeds the auto-start batch and is rejected at startup under udp in the same way.

TCP refuses where UDP degrades​

Under UDP a device that cannot bind its own socket falls back to a shared one, losing source-address attribution and nothing else. TCP has no shared connection, because one stream carries no field to tell devices apart.

RuleBehaviour
ConnectionsOne per device, never shared, dialled from inside the device's network namespace so the source address is the device's own.
-syslog-source-per-device=falseA TCP or TLS attach fails.
AttachSucceeds once the reconnect loop is running. The collector does not need to be up.
ReconnectCapped backoff. The backoff resets only after a connection has survived long enough to count as working, so a collector that accepts and immediately closes is not re-dialled every second.
KeepalivesOn, so a collector that dies without closing (host crash, partition) is detected on an idle connection.
Send bufferCapped per connection rather than auto-tuned, so a stalled collector is noticed in seconds.
Stalled writeDropped after a short bound and the connection replaced. A write never blocks the scheduler.

What sent means under TCP​

GET /api/v1/syslog/status rows carry a transport field, so TCP and UDP devices sending the same format to the same collector do not merge into one row. On the datagram path sent approximates "on the wire". On TCP it means "handed to the kernel", and under load those differ by however deep the send buffer is.

TLS (RFC 5425)​

transport: "tls" carries the same stream inside a TLS session. Every TCP rule above applies. Three things differ:

framingonly octet-counting is accepted. An empty framing defaults to it. RFC 5425 §4.3.1 mandates it, so any other framing is rejected with 400 at configuration rather than overridden.
default port6514 where the other transports use 514 (RFC 5425 §4.1).
verificationthe collector's certificate is verified. TLS 1.2 is the floor and is not configurable.

A bare hostname changes port when you change transport. "collector": "logs.example" means logs.example:514 under udp and tcp, and logs.example:6514 under tls. Give the collector an explicit port if you do not want that.

What is verified, and by whom​

nl6 is the client here. It verifies the collector and presents no certificate of its own. The shared certificate the HTTPS API and gNMI dial-in present is not used on this path.

fieldeffect
tls.ca_pemPEM bundle used to verify the collector, inline. Capped at 64 KiB.
(omitted)verify against the host's root store
tls.insecure_skip_verifydisable verification (development only). The CLI seed equivalent is -syslog-tls-insecure.
tls.mtlsnot implemented, rejected at configuration rather than ignored

The REST field takes inline PEM, never a file path. On the command line -syslog-tls-ca names a file, read once at startup. Whatever the source, only CERTIFICATE blocks are kept; a private key in the bundle is discarded, because GET /api/v1/devices echoes this config.

With no ca_pem and no explicit insecure_skip_verify, a collector the host does not trust fails to connect.

TLS adds record buffers per connection on top of the capped socket buffer, so size a TLS fleet above the plaintext per-device cost.

Collector-side caveats​

Collector sizing, rp_filter and the relay pattern for collectors without TCP are in Send syslog over TCP or TLS.

HTTP endpoints​

Fire a syslog message on demand​

POST /api/v1/devices/{ip}/syslog fires one message for the named device immediately, bypassing the Poisson scheduler and the global rate cap. Body:

{
  "name": "interface-down",
  "templateOverrides": {
    "IfIndex": "7",
    "IfName": "GigabitEthernet0/7"
  }
}

name is required and must match an entry in the device's resolved catalog (per-type overlay if present, universal otherwise). templateOverrides is optional. Supplied keys pin the corresponding template field for this fire only. Only the twelve fields of the template vocabulary are accepted.

Responses:

StatusBodyWhen
202 Accepted{}Success; the message was emitted.
400 Bad Request{"error": "...", "catalog": "<slug>", "availableEntries": [...]}Unknown catalog entry for the device. The body names the catalog the device resolved to and lists its entries.
404 Not Founderror JSONUnknown device IP.
503 Service Unavailableerror JSONThe syslog subsystem has not started or the target device has no syslog config (i.e. it was created without a syslog block and didn't inherit the CLI seed).
500 Internal Server Errorerror JSONInternal error; report it as a bug.

On-demand fires do not consume global rate-cap tokens.
