Install with Ansible

The labmonkeys.nl6 Ansible collection installs nl6 from its native package and runs it under systemd. Its one role, nl6, downloads the .deb or .rpm for the host from the GitHub release and verifies it against the release checksums.txt. It installs the package with apt or dnf, so ip, iptables and sysctl resolve as package dependencies. It then sets the sysctls, writes /etc/nl6/nl6.conf and enables the packaged nl6.service.

PlatformPackagePackage manager
Ubuntu 24.04, 26.04nl6_<version>_<arch>.debapt
CentOS Stream 10, Rocky Linux 10, AlmaLinux 10nl6-<version>-1.<arch>.rpmdnf

Both amd64 (x86_64) and arm64 (aarch64) are supported. Any Debian-family host gets the .deb. A RedHat-family host other than EL 10, or a host of any other family, fails before the role downloads anything. It installs the same package as Install packages. It also sets the sysctls and runs the checks below, which the manual install leaves to you.

Before you start​

  • Pick the simulator interface. nl6_net_interface is required. It names the host NIC that faces the simulated network, and the role fails if it does not exist.
  • Check the FORWARD policy. Traffic from a collector to the simulated devices needs the iptables FORWARD policy to be ACCEPT. Docker and ufw set it to DROP, and the role fails then. See Firewall rules.
  • Check firewalld. If firewalld is active, configure it to forward between the collector and the simulated network. The role warns when firewalld is active but cannot check its policy.
  • Allow internet access, or use a mirror. Each run fetches checksums.txt from github.com. See Internet access.

Install the collection​

The collection lives in the nl6 repository under deploy/ansible. Install it by git tag:

ansible-galaxy collection install 'git+https://github.com/labmonkeys-space/nl6.git#/deploy/ansible,vX.Y.Z'

Or list it in requirements.yml:

collections:
  - name: https://github.com/labmonkeys-space/nl6.git#/deploy/ansible
    type: git
    version: vX.Y.Z

The collection version always equals the nl6 release. Collection X.Y.Z runs nl6 vX.Y.Z by default.

Releases older than the collection have no deploy/ansible directory. If ansible-galaxy reports that the path does not exist at your tag, that release predates the collection. Install from main instead by replacing vX.Y.Z with main.

Run the role​

- hosts: simulator
  become: true
  roles:
    - role: labmonkeys.nl6.nl6
      nl6_net_interface: enp2s0

The play ends by polling the nl6 API and prints the version that answered.

What the role guards against​

  • Wrong interface. With a bad nl6_net_interface the sysctls below land on nothing and device traffic is dropped silently. The role asserts the interface exists.
  • Unverified download. The package is checked against the release checksums.txt. A custom nl6_package_url needs an explicit nl6_package_checksum.
  • Reverse-path filtering. The role sets net.ipv4.ip_forward=1 and rp_filter=0 for all and for nl6_net_interface.
  • Crash loop. Restart=on-failure turns a rejected argument into a restart loop while systemd reports "started". The role polls /api/v1/version for up to 60 s and fails if nl6 does not answer.
  • Unusable extra args. See NL6_OPTS word-splitting.
  • Version bump. See A version bump wipes the fleet.

Things to know​

A version bump wipes the fleet​

nl6 keeps devices in memory only. The package postinstall runs systemctl try-restart nl6.service, so installing a different version restarts nl6 and every simulated device disappears. The role reads the installed version with dpkg-query or rpm -q and prints a warning when nl6 is installed and active and the version differs from nl6_version. To keep the fleet, save it with fleet.sh export before you change nl6_version. Replay it with fleet.sh import after the play finishes.

Config changes restart nl6​

A change to /etc/nl6/nl6.conf restarts nl6 through a handler, which also wipes the fleet.

Firewall rules​

nl6 inserts a FORWARD ACCEPT rule for its own veth when it sets up its network namespace. That rule covers traffic leaving the namespace only. See Network namespace for the rule itself. Traffic from a collector to the devices relies on the FORWARD chain policy being ACCEPT, which is true on a stock Ubuntu cloud image. Docker and ufw set the policy to DROP. The role reads iptables -S FORWARD and fails when the policy is not ACCEPT. On such a host, allow forwarding to and from the simulated network yourself, or set the policy, before running the role.

firewalld filters forwarded traffic in its own nftables table, which iptables -S FORWARD does not show. On a firewalld host the FORWARD check can pass while firewalld still drops collector traffic. The role prints a WARNING when firewalld.service is active and continues. The role installs no firewall rules and no routes, so routing into the simulated network is up to you.

Internet access​

Each run fetches checksums.txt from github.com, so the host needs internet access. Set nl6_package_url and nl6_package_checksum to use a mirror instead.

Check mode​

In check mode the role skips the package install, the FORWARD policy read and the FORWARD policy assert. The other asserts still run.

NL6_OPTS word-splitting​

The unit runs nl6 $NL6_OPTS with EnvironmentFile=-/etc/nl6/nl6.conf. systemd splits the value on whitespace and has no quoting or escaping there. An element of nl6_extra_args therefore cannot contain whitespace, and the role also rejects ", $ and %, which break the quoted assignment or get expanded. Pass each flag and each value as its own list element, for example ["-auto-count", "5"]. nl6_pyroscope_url is checked the same way.

Profiling​

The role configures push mode only. Go allows one CPU profile at a time, so while the SDK pushes, a puller asking /debug/pprof/profile gets a 500. See Profiling.
