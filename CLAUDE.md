## Architecture

**nl6** is a Go-based network device simulator capable of running 30,000+ concurrent simulated devices, each responding to SNMP (v2c/v3), SSH, and HTTPS REST protocols. It uses Linux TUN interfaces and network namespaces to give each device its own IP address.

### Package layout

| Path | Purpose |
|------|---------|
| `go/nl6/` | Core simulator — all device simulation logic and tests |
| `go/nl6/resources/` | 389 JSON files (29 device types) with SNMP/SSH/REST response data |

### Core simulator components (`go/nl6/`)

**Device lifecycle:** `simulator.go` (CLI/entry) → `manager.go` (SimulatorManager, shared keys/certs) → `device.go` (per-device startup, protocol server lifecycle)

**SNMP stack:** `snmp_server.go` → `snmp.go` (request handling) → `snmp_handlers.go` (OID lookup via sync.Map) → `snmp_response.go` (response building) → `snmp_encoding.go` (ASN.1 BER/DER).

**SNMP response size (nl6#489).** `maxSNMPResponseSize` is a FRAME bound derived from `linkMTU` and refreshed by `recomputeDatagramBudgets`, so it tracks `-datagram-mtu`; udp4 only. **GETBULK truncates** (RFC 3416 §4.2.3: a walk resumes from the last OID returned) but **GET and GETNEXT return `tooBig` with an empty binding list** (§4.2.1: the requester has no resume point, so a partial answer is an undetectable wrong answer). All three PDU types share `createVarbindResponse` deliberately, so the rule is an explicit `snmpOverflowRule` argument rather than something the encoder infers. Getting it backwards is the most damaging mistake available here. Sizing is exact and incremental via `snmpMessageSizeFor`, never estimated: every bug in this family was a predicted size disagreeing with an emitted one. SNMPv3 GETBULK is bounded by MEASUREMENT rather than arithmetic (its envelope is not fixed), bisecting to the largest prefix that fits. The GETBULK **walk** is separately clamped by `minVarbindSize`, a CPU guard rather than a correctness one (a walk step is expensive: ~29 req/s already saturates cores on the LLDP path), and it is deliberately an under-estimate so it never under-fills.

**SNMP exceptions and SNMPv1 (nl6#517, #526, #535, #547).** An absent OID is answered `noSuchObject`, never `noSuchInstance` and never a string. Exceptions travel from lookup to encoder as **sentinel strings** (`valueNoSuchObject`, `valueEndOfMibView`), which is a value-space hazard: a resource value literally spelled `noSuchObject` would encode as an exception. That is what the load-time guard exists to stop. **SNMPv1 has no exceptions**, so a sentinel diverts to `error-status = noSuchName` with the request's names echoed and NULL values. The diversion covers GET and GETNEXT via an explicit `v1DiversionRule` argument (`v1DivertSentinelAndCounter64` / `v1DivertSentinel` / `v1DivertNothing`); GETBULK is excluded because it does not exist in v1. On the GETNEXT path the echoed names are passed SEPARATELY (`echoNames`), since its `oids` are successors rather than requested names.

**v3 GETBULK rules that are easy to break.** A terminating walk answers `{requestedOID, endOfMibView}`: naming the binding with what was ASKED FOR is load-bearing, because an exception on a wrongly-named binding fixes only half the problem. `createScopedPDUMulti` is the single scoped-PDU builder and `wrapScopedPDUInV3Message` the single envelope, split out precisely so GETBULK could not grow a second encoder to drift against. `max-repetitions` and `non-repeaters` are honoured, clamped at the PARSE SITE, and read at any BER width (benchmark numbers taken above 127 before that fix are not comparable with ones after it). `clampBulkWalk` DIVIDES its ceiling by the repeater-column count so it bounds the total. `largestFittingPrefix` BISECTS rather than descending. A multi-column response is byte-identical to v2c, tail included, and the rule is keyed on LOOP SHAPE, not version: the single-column loop stops, the multi-column loop pads. A declared CONTAINER length that overruns what contains it is MALFORMED, not absent, at every container. `max-repetitions = 0` is an EMPTY binding list, never the `len(oids) == 0` end-of-MIB branch.

**Counter64 under SNMPv1 (nl6#524, #542).** Counter64 does not exist in v1 and `encodeTypedValue` picks the tag from the OID alone. RFC 3584 §4.2.2.1 prescribes **two different behaviours and the asymmetry is the whole design**: a **GET** diverts to `noSuchName`, a **GETNEXT SKIPS** the object and continues. A GETNEXT names a position rather than an object, so erroring there would stop a v1 walk dead at the first HC column and truncate the table with no signal. The test is on the OID's DECLARED type, not on what the value encodes as. The GETNEXT path takes ONE `lldpServedOIDs()` snapshot for the first step and the skip run (reused via `findNextOIDWithServed`), because calling `findNextOID` in a loop rebuilds the device's whole LLDP view per step.

`longestShippedCounter64Run` is measured by WALKING `findNextOIDWithServed`, not by scanning `sortedOIDs`: the walk also offers `ifCycler.NextDynamicOID`, which is worth 4x (1152 steps, not 288). It is the numerator of `counter64SkipBudgetSteps()`, so an unmeasured long HC run under-sizes a serve-path budget. The version test comes first and is free; reversing it would put a linear type-table scan on every GETNEXT of every version. GETNEXT answers EVERY binding since nl6#542, with two CPU guards whose shape is the reverse of GETBULK's: the skip allowance is a budget shared by the whole DATAGRAM (a per-binding cap would multiply), and the binding count is clamped by `maxGetNextBindings()` with anything above it answered `tooBig` WITHOUT WALKING. Coverage is bounded by `oidTypeTable`; v1 GETBULK is deliberately untouched.

**SNMPv3 USM is RFC 3414 conformant and externally verified (nl6#624).** Before it, there was no HMAC anywhere, `AuthProtocol` was read by no production code, the two privacy derivations hardcoded opposite hashes, and the engine ID went on the wire as the ASCII of its hex spelling. They had to be fixed TOGETHER, because a manager localizes its key with the engine ID it RECEIVED.

**The external check is the load-bearing part.** `snmpv3_usm_interop_test.go` drives the real dispatcher over a real UDP socket with net-snmp, including a wrong-password control, and **its first run failed all six rows with the package green**: the fix had corrected one emitter and left three others sending the old engine ID. Nothing in the package compared one emitter against another; `TestEveryEmitterAgreesOnTheEngineIdentity` now does. Key derivation is verified against RFC 3414 Appendix A.3's PUBLISHED vectors parsed from a checked-in RFC extract (`testdata/rfc/`), not against nl6's own output. `make test-interop` is a CI gate.

**Rules that look like tidy-ups and are not.** `locateAuthParams` WALKS the message structure; the byte search it replaced was defeatable by a served value of twelve zero octets. The AES IV and `msgAuthoritativeEngineTime` come from ONE clock sample (`encryptScopedPDUAt`), and the verification half mattered more than the fix: decrypting with the server's live clock left both sides agreeing by accident. Verification is conditional on the REQUEST's auth flag, not the device's configuration. `usmPasswordToKey` caches Ku across devices. **Not implemented:** SNMPv3 INFORM, RFC 7860 SHA-2, AES-192/256. **Two engine-identity limits stand:** `snmpEngineID` is fleet-wide while `(boots, time)` is per device, and `engineBoots` is always 1 and not persisted.

**SNMP resource value guard (nl6#523, #529).** `validateSNMPResourceValues` rejects a resource response whose value is an exception sentinel, naming file, OID and value; the test is EXACT, and the error says that OMITTING the entry is how you make an OID answer `noSuchObject` on purpose. Scope is the `snmp` array only. It is wired at the **four loaders a resource file can reach**, validated per JSON *part* so the error names the file rather than the directory; `createDefaultResources` writes compiled-in constants and is deliberately not guarded. Rule 2: a value on an OID-typed leaf must be one `encodeOID` can represent, decided by CALLING `encodeOID` and testing for the degenerate `06 00`, never by a second predicate that agreed on the day it was written. The sentinel rule is checked FIRST, matching `encodeTypedValue`'s order. OID **keys** remain unchecked, and `sysName` / `sysLocation` are served outside the resource map.

**The typed-class rule (nl6#541).** Rule 3: a value on any leaf `oidTypeTable` types must encode AT that type, decided by CALLING the encoder (`encodeTypedValueAtTag`) and comparing the emitted tag with the declared one. The numeric and address branches fall through to `encodeOctetString` when parsing fails, which is the silent degradation this catches. **Two declared types are skipped** because their branches cannot degrade: OCTET STRING (accepts anything) and OBJECT IDENTIFIER (answers `06 00`, whose tag IS the declared one, which is why rule 2 cannot be folded in). The rule INHERITS the encoder's asymmetries rather than tidying them: a negative on Counter32/Gauge32/TimeTicks loads with a WARNING (the encoder wrap-casts), the same value on Counter64 is refused. Making the guard disagree with the encoder is the failure to avoid.

**The nl6#541 data edits.** Rule 3 found 45 entries; the other edits were found by DIFFERENT tests (`TestShippedBigValuesSitOnCounter64Leaves`, `TestShippedUntypedValuesFitInteger32`) because they sit on leaves the table does not type. The whole transition is committed as data and re-derived against the parent revision's digest, not summarised: a count is not a measurement a reader can check.

**Bare columns and over-specified instances (nl6#571).** A varbind name must be an INSTANCE, with exactly as many trailing sub-identifiers as the table's INDEX clause says. **The detector is a HEURISTIC and it inverted on first use**: "some other shipped OID extends it" fails exactly when the EXTENDING sibling is the malformed one, and the first cut deleted the legal name and kept the illegal one in four profiles. A hit is a CANDIDATE TO CHECK AGAINST THE MIB, never a verdict. **The scan is corpus-wide and narrowing it is the regression to guard against**: legality is a property of the OID, not of which profile carries it, and a same-profile scan missed 20 of 61. A test asserting ZERO of something cannot fail on its own, so both guards open with a positive control that plants a column in profile A and its instance in profile B. **Four profiles now model no storage and that is CORRECT: do not restore the row to make the table non-empty.**

**A trap and a poll must agree on type (nl6#593, #607).** A trap catalog DECLARES a varbind's ASN.1 type; the resource `snmp` array separately decides the type of a GET of that OID. Two validation paths, and nothing joined them, so one profile could answer one object at two types depending on how it was asked. **Both tags come from the PRODUCTION encoders**, and the trap side READS THE TAG BACK OUT of the encoded varbind rather than mirroring the encoder's switch. **The probe is for templated values and nothing else** (`strings.Contains(value, "{{")`): falling back to a probe on any encode error launders real defects into agreement. Duplicated and shadowed OIDs are REPORTED, never resolved by picking. An unserved varbind is normal, not a finding. A second rule checks that a catalog does not contradict ITSELF, which reaches two surfaces the join cannot: a catalog that joins zero resource entries, and every templated varbind. Census constants are re-derived each run, and the control has eight arms because a rule that goes quiet is indistinguishable from a clean corpus.

**The widened Counter64 table.** `oidTypeTable` gained the RFC 4293 HC columns and the RFC 3635 `dot3HCStatsTable` columns, read out of the shipped MIBs with `snmptranslate` rather than recalled (a hand-recalled list was wrong on every entry). The test does NOT shell out to net-snmp: MIB facts are extracted and checked in under `go/nl6/testdata/mibs/`, because no workflow installs it and a `t.Skip` in CI asserts nothing. Unresolved rows are COUNTED so a new standard row cannot hide in that bucket. **Widening a type table is a WIRE change**, so it was measured: the (profile, OID, emitted tag) digest taken before still matches after. Effect on the shipped fleet is exactly zero; the value is for operator files.

**The corpus guards must see BOTH layouts.** A device type ships as a directory of parts OR as a single `resources/<slug>.json`. The corpus walkers once globbed two path segments, so a single-file profile bypassed every guard and **the only test that fired told the maintainer to re-pin a golden digest**, which would have absorbed the defect. `snmp_shipped_corpus_test.go` is now the one recursive walk every corpus test uses, and a test plants a single-file profile in a temp tree to require the walk to see it.

**`snmpTypeTag`'s scan** runs once per encoded value on every response of every version, so the comparison is allocation-free rather than concatenating per row per call. The evidence is a committed A/B over the same table plus an equivalence pin and a fuzz target. Absolute figures do not travel between machines; run the benchmark rather than quoting a number.

**`sysLocation` and `sysName`.** The sentinel rule for `sysLocation` is enforced ONCE AT LOAD (`dropSentinelLocations`) over the assembled slice. Per-device filtering cost up to 30,000 log lines at fleet start with the bad row still in the slice, and diverting a draw silently discarded the device's coordinates. The filter's WIRING is pinned through the FALLBACK branch (`fallbackCities` is a package-level var so a test can swap in a sentinel-bearing set); deleting the call used to fail no test at all. `sysName` embeds the operator's `resource_file` slug, and is safe for two independent structural reasons (every pattern embeds `-`, and the result is lower-cased while both sentinels are camelCase).

**The rules check ENCODABILITY, not SEMANTICS.** Nothing in them says an OID means what the MIB says it means: a value that encodes cleanly at its declared type passes even when the object at that OID is a different object entirely, or does not exist. **Read the guards as "nl6 will not put a mistyped BER value on the wire", never as "this profile is faithful to the MIB".**

**The conclusion worth keeping: the corpus is not uniformly fabricated, it is SPLIT.** What someone read a MIB for is right; what nobody did is mostly wrong. nl6#601's own stated expectation ("no reason to think this arc is better") was wrong for a reason visible before the audit started: provenance predicts the result, and a catalog citing aggregators resolved every OID while the polled data beside it, citing nothing, missed 13 of 15.

**Rules the audits established.** Count distinct OIDs and entries SEPARATELY. **No MIB file or extracted fixture is checked in for a VENDOR module**, deliberately: no vendor of the nineteen surveyed publishes a redistribution grant, so each audit is a PINNED READING citing module and revision, never a live check. A subtler defect than an unresolvable OID is one that RESOLVES to the wrong thing: `juniper_mx960` answered `sysObjectID` with a real Juniper chassis nl6 does not model, so vendor detection succeeded and was wrong. Deleting rows can legitimately empty a table, and that is correct: **do not restore a row to make a table non-empty.** A walk from a PEN root needs a POSITIVE CONTROL, because OIDs sort as strings and an empty answer satisfies "no successor under the arc" just as an aborted walk does. Read the MIB's product NAME, not the ASN.1 identifier. Model identity is PROFILE-WIDE, not a `sysDescr` rule: correcting one surface can replace a fake-vs-fake split with a real-vs-fake contradiction, which is worse.

**The ledger chain is stated ONCE, here.** Every data edit moves both golden digests and needs a chained reversal that walks back from today's corpus to `44ef67f`. A new audit adds ONE entry to `newestFirstReversals` in `snmp_shipped_corpus_reversals_test.go` (nl6#600) and nothing else; the registry requires every `*_ledger_test.go` to contribute exactly one entry, requires the chain to be contiguous, and requires an absent view to carry a recorded reason. A change that reverses nothing must NOT be named `*_ledger_test.go`.

**Every vendor arc is audited, deliberately labelled, or explicitly excluded (nl6#590).** `TestEveryVendorArcIsAuditedLabelledOrExcluded` groups arc hits into (profile, PEN) pairs and requires EXACTLY ONE disposition per pair: the PEN sits in `auditedArcPENs` naming the reading test that pins it, or every part carrying the arc has `UNAUDITED-ARC(<pen>)` in its `_comment`, or the pair is in `excludedArcPairs` with a written reason. **A new device type that serves a vendor subtree and does none of the three FAILS BY NAME.** That is the durable deliverable: nothing previously stopped the corpus regrowing this problem.

**Fourteen arcs were closed BY DECISION, not by audit.** Cross-referencing every arc against every consumer in this repo found that only four have any consumer, and all four are audited. At the observed miss rate an audit is weeks of work producing deletions of data nothing reads, while a label is minutes and is MORE HONEST THAN SILENCE: a reader who opens the file sees a vendor subtree and reasonably infers somebody checked it. **The marker is per PART, not per profile** (14 profiles, 19 parts), and carries the PEN, so a profile that later gains a second arc cannot inherit the first one's label. **What no test can do is check that a label is TRUE**; what it refuses is the fourth state, a vendor subtree that reads as checked because nothing says otherwise. The positive control has two arms, because a rule that reported every arc it saw would pass a one-armed control.

**No nl6 rule models MAX-ACCESS (nl6#591).** The load rules check encodability, the PEN guards check vendor identity, the reading tests check names and types. None models ACCESS, and none can, because it is a property of the MIB. `writeMem` (`ACCESS write-only`, a COMMAND whose write erases config memory) was answered with a large number by two profiles and passed every guard, because the object exists, the arc is right and the value encoded at the declared type. **Deleted, not corrected**: a write-only object has no correct readable value. Cited by name and FORM rather than revision, since SMIv1 modules carry no `MODULE-IDENTITY`. **`not-accessible` is the larger, unswept half**: every SMIv2 table INDEX column belongs to it, and it advances only with a per-arc MIB reading.

**Version-0 GETBULK is unchanged by decision.** **Still uncovered:** OID KEYS; leaves `oidTypeTable` does not type; vendor HC columns; a bare column that NOTHING in the corpus extends (indistinguishable from a scalar without a MIB); ACCESS MODES; wrong INDEX ARITY generally; and SEMANTIC faithfulness of the objects below a correct PEN. Cross-vendor OID contamination is CLOSED as a class by nl6#588. "The census reads zero" means no entry is an interior node of the shipped set, NOT that every shipped name is a legal instance.

**A wrong-owner enterprise arc (nl6#576).** The three `nvidia_*` profiles served GPU telemetry under a PEN IANA allocates to an unrelated company, so a collector doing vendor detection on a simulated DGX resolved it as that company. The arc moved to NVIDIA's real PEN preserving **every sub-identifier below the PEN**, so a downstream rule needs only its prefix updated. The live half moved too: `nvidiaGPUMetricPrefix` drives 64 dynamic OIDs per device, and re-homing the JSON while leaving it behind is the mutation the guard exists to catch. **The premise is checked in as data** (`testdata/iana/enterprise_numbers.tsv` with source URL, fetch date and command), because it was the only claim nothing else could falsify. **The residual, recorded rather than fixed:** NVIDIA publishes no SNMP GPU MIB, so the objects below the PEN remain nl6's invention, now attributed to NVIDIA rather than to a stranger.

**Every profile serves its own vendor's PEN and no other (nl6#588).** A vendor enterprise subtree is an IDENTITY CLAIM, not an approximation; four instances of the same defect shipped before this closed the class. Four things in the guard are load-bearing, each a defect already shipped once. (1) It reads OID-typed VALUES as well as names: vendor detection reads the `sysObjectID.0` response, not an OID key, so a name-only scan is blind to the exact regression it exists to catch. (2) Its positive control plants ACROSS profiles and is scoped to the planted profiles, so it stays trustworthy while a real violation exists elsewhere. (3) `ownVendorPENs` is CURATED with a mandatory reason per row, never derived from string similarity: six shipped pairs share no word with their slug and are all correct. (4) `arcPENOf` matches on a SUB-IDENTIFIER BOUNDARY, since PEN 2 is a string prefix of four other shipped PENs. **RFC 5612's documentation PEN 32473 is a PER-PROFILE allowance, never globally permitted**: making it general would give any future profile a way to dodge the guard. **The two single-arc guards STAY**, because they say something this one does not, namely that those two specific arcs must not come back by name.

**The guard covers three surfaces and two held a live defect**, which is the argument for a general guard over another single-arc one: `vendorOIDs` in Go code served one profile a digit-transposed PEN never read by any test, and `createDefaultResources` (a PRODUCTION fallback) identified device with no resource file as Cisco hardware. Neither moves a golden digest, because the corpus walkers see resource files only. **In the VALUE position the scan sees `sysObjectID` and nothing else**, because the gate is the production predicate and `oidTypeTable` has one OBJECT IDENTIFIER row; widening it means adding a row, which is a wire change.

**Dynamic IF-MIB counters (`if_counters.go`).** `IfCounterCycler.GetDynamic` serves per-interface `ifTable` / `ifXTable` counters analytically, with no per-interface goroutine. `ifHCInOctets` / `ifHCOutOctets` are the master dial; Counter32 shadow columns return the low 32 bits of the matching HC column. **The low-32 equality is a DE-FACTO convention, not an RFC 2863 mandate** (§3.1.6 mandates only which WIDTH to serve at which speed); deriving one from the other is nl6's choice. **The shadow is DERIVED at read time from the same `t` the HC column used, never stored**: a second clock read reintroduces exactly the divergence the fix removed. The identity is exact only for a caller passing ONE `t` across both columns (sFlow counter samples, gNMI); the per-OID SNMP path re-reads the clock per call and drifts, which is a property of the read API and is pinned as a caveat so the wording cannot drift back to an unconditional claim. `ifCyclerColumns` is in strict MIB lex order and doubles as the walk enumeration, so a wrong insertion point is a non-increasing walk rather than a wrong value.

**The dead-data rule, and the one carve-out.** A static row on a cycler-owned column is served by nothing (`findResponse` consults the cycler first), so it is dead data that looks authoritative; 1322 + 742 such rows were deleted. **`.7` `ifAdminStatus` and `.8` `ifOperStatus` keep their static rows and must NEVER be deleted**: `InitIfCountersWithScenario` reads both out of `oidIndex` as the device's initial state, so they are live input, not dead shadows. The precondition for deleting a row is that the cycler knows its ifIndex, built exclusively from ifXTable `.6` keys. The corpus guard fires on the DEFECT rather than on a digest, because a digest's documented remedy is to RE-PIN, which is a guard whose failure mode destroys the evidence.

**Interface state engine (`interface_state.go`, added by add-interface-state):** `IfCounterCycler` owns an `InterfaceState` per device that stores `oper-status` / `admin-status` / `last-change` per ifIndex in a packed `atomic.Uint64` slot (3 bits + 3 bits + 58 bits wall-relative ns). `ifAdminStatus.<N>` (`.7`), `ifOperStatus.<N>` (`.8`), `ifLastChange.<N>` (`.9`) are now claimed by the cycler — `GetDynamicAt` reads them from the state engine, so SNMP and gNMI agree byte-for-byte at the same instant. Mutators are `SetOperStatus` / `SetAdminStatus` (CAS-loop, idempotent on no-op), fed by two sources: the flap scheduler (`flap_scheduler.go`, single shared min-heap goroutine driving Poisson-distributed flaps per (device, ifIndex) — same shape as `trap_scheduler.go`) and the REST control plane (`POST /api/v1/devices/{ip}/interfaces/{ifIndex}/{oper,admin}-status`). State transitions broadcast a `StateChange` event to every registered ON_CHANGE Subscribe listener via a per-stream depth-16 channel with drop-oldest on overflow. Cross-protocol consistency in Tier B: SNMP, gNMI Get, and gNMI Subscribe ON_CHANGE all see the same value at the same instant. **Tier C (`correlate-state-notifications`):** an oper-status transition now also fires correlated link traps + syslog for that ifIndex — `InterfaceState.SetNotify` installs an `atomic.Pointer[func(StateChange)]` hook invoked (oper-only, gated on `LeafOperStatus`) at the end of `Broadcast`, after the slot store commits. The manager wires it at trap/syslog attach time (`wireStateNotify`) to call `FireForInterface(entry, ifIndex)` on the role-matched catalog entries (`EntriesByRole`, vendor-wins-per-role); the closure snapshots the exporters under `device.mu.RLock` and fires outside the lock (closing-guard handles teardown). Covers all three mutation sources (REST, flap scheduler, REST auto-revert) via the single `Broadcast` funnel. Link telemetry volume now rides real state changes (`-if-flap-scenario` / REST), and state-driven fires bypass the Poisson global cap on initial transmit.

**The state engine's clock is injectable (nl6#575).** `InterfaceState` takes a now-source normalised to `time.Now`, matching the four other clock seams rather than inventing a fifth shape. **THREE reads move together and that is the load-bearing part**: `bootTimeUnixNs` is the origin every relative `lastChange` is measured from, so an engine whose boot time came from the real clock and whose transitions come from an injected one subtracts a real timestamp from a fake one. **The sample stays INSIDE the CAS loop** so a retry stamps the winning attempt; hoisting it reads as a harmless refactor and makes `ifLastChange` go backwards under contention (measured: 12,030 backwards reads in 100ms with 8 writers), and the whole package stayed green with it hoisted until a test pinned it. NOT `synctest`: a bubble serialises goroutines and would remove the real parallelism the torn-read assertions exercise. An injected clock MUST return a positive `UnixNano`.

**REST auto-revert convention.** `POST .../oper-status` and `POST .../admin-status` accept an optional `duration` field (`{"status":"DOWN","duration":"30s"}`). When set: (1) the handler snapshots the pre-mutation slot value at POST time; (2) `SimulatorManager.revertTimers` registers the timer keyed by `(ip, ifIndex, isOper)` so a subsequent duration POST on the same leaf cancels the first; (3) `device.Stop()` cancels per-device timers, `manager.Shutdown()` cancels all; (4) `duration` is capped at 24h (`maxRevertAfter`) — over-cap returns 400; (5) on-demand HTTP fires bypass the flap scheduler's `-if-flap-global-cap` rate limiter, matching the trap/syslog convention for test-harness use.

**Metrics engine:** `metrics_cycler.go` drives 100-point pre-generated sine-wave patterns per device. `gpu_metrics.go` handles per-GPU metrics (utilization, VRAM, temperature, power, clocks). `device_profiles.go` defines per-category baselines.

**Network infrastructure:** `tun.go` creates TUN interfaces, `netns.go` manages the `nl6sim` network namespace, `prealloc.go` does parallel pre-allocation of TUN interfaces (configurable worker count 100–200) for fast scaling.

**Allocation-state locking on the device-creation path (nl6#556).** Which lock governs which field: **`sm.mu`** for `nextTunIndex`, `currentIP`, `tunPoolSize` and `maxWorkers`; **`tunPoolMutex`** for `tunInterfacePool` — its entries AND the map value, since a mutex that guards a map's contents does not guard replacing the map. Lock order where both are needed is **`sm.mu` → `tunPoolMutex`**, established by `shutdownFast`; `CleanupPreAllocatedInterfaces` therefore clears `tunPoolSize` under `sm.mu` BEFORE it takes the pool lock (doing it after left `GetStatus` reporting a pool size against an already-emptied pool for the whole duration of the bulk `ip -batch` delete). **No lock is held across interface CREATION** — not `ip link add`, `createTunInterface*`, or the `ip -batch` delete: the pre-allocator runs up to 500 workers and serialising them would destroy the feature. The claim stops at creation deliberately: `tunIface.destroy()` is a `syscall.Close` per interface and DOES run under `tunPoolMutex` in `CleanupPreAllocatedInterfaces`, and under both locks in `shutdownFast` — pre-existing, on shutdown paths, and untouched by nl6#556.

At the time of nl6#556 nothing excluded two concurrent creates from each other (`createBatchGate` now does — see nl6#565 below; `isCreatingDevices` is a UI status flag, `fleetFreezeCheck` only rejects during a scenario freeze window, and the auto-start goroutine runs alongside the HTTP server, so a pre-allocation batch really could overlap a `POST /api/v1/devices`). Within a batch the mechanism is still **reserve-then-work, not lock-around-work**, and it has to be, since the gate does not serialise a batch's own workers: `reservePreAllocBatch` commits `tunPoolSize`, `maxWorkers`, the `nextTunIndex` base and the batch's end `currentIP` in ONE `sm.mu` critical section BEFORE any worker starts, and returns the base, which the workers use to build their names. A worker must never read `sm.nextTunIndex` — reading it was the actual defect, since a concurrent `getNextTunName` moved the base mid-batch and two workers of the SAME batch could compute one name, failing the second `ip link add` — and the index and the IP must move in the same critical section so no reader sees one advanced against a stale other. Advancing at the START also stops the 5-minute timeout return from leaving the index behind interfaces already created (that timeout still DETACHES its workers, which keep creating interfaces after the caller has fallen back; the reservation is what makes that merely wasteful).

**What nl6#556 does NOT close: IP allocation.** Only the TUN index is genuinely reserved. `CreateDevicesWithOptions` rewinds `currentIP` to the batch start right after pre-allocation returns — necessarily, since the devices must land on the addresses the pool was created with — so `currentIP` is a shared cursor and two overlapping batches can still hand out overlapping device IPs. `tunPoolSize` and `maxWorkers` are likewise **last-writer-wins** across concurrent batches: batch A's `createDevicesParallel` can size its semaphore from batch B's worker count, and A's summary log can print B's numbers. Locking made those race-free, not correct. Closing either needs one-batch-at-a-time exclusion, which is a behaviour change, so nl6#556 reported it and **nl6#565 adopted it** (next paragraph).

**One creation batch at a time, and a concurrent one gets 409 (nl6#565).** `createBatchGate` (`types.go`, beside `isCreatingDevices`) is a `sync.Mutex` that `CreateDevicesWithOptions` **try-locks** at entry; a second concurrent batch is refused with the sentinel `errCreateBatchInProgress`, which `createDevicesErrorResponse` maps to **409 Conflict** via `errors.Is` (the nl6#538 `errResourceInvalid` shape) with `Retry-After: 5`. Fail-fast, not a queue: a 30k batch would make a small create wait minutes with no feedback, and an HTTP client that times out mid-wait cannot tell whether its batch ran. **This is a real API behaviour change** — two parallel `POST /api/v1/devices` used to interleave — and the `-auto-start-ip` batch counts as a batch, so a REST create issued during fleet startup 409s until startup finishes; `scripts/fleet.sh import` therefore RETRIES on 409 (`RETRY_409_LIMIT`/`RETRY_409_DELAY`), which is what keeps `compose up`'s bootstrapper working with an auto-start batch configured. The console's Clos wizard does not retry and leaves a half-built fabric; that is stated in `docs/reference/web-api.md` rather than fixed.

Four things are load-bearing. (1) The gate is **THE MUTEX and `isCreatingDevices` is THE STATUS FLAG**: the latter is an `atomic.Value` published AFTER entry and read by `fleetFreezeCheck`, so a check-then-set on it is racy by construction — it had already been mistaken for a lock once. (2) The gate must span **the reservation AND the IP walk**, which is why the body moved into `createDevicesWithOptionsLocked` and the wrapper holds the gate across the whole call with `defer` (panic included): gating only the reservation leaves the walk, where `currentIP` is actually consumed, unprotected, which is exactly the difference between nl6#556 fixing TUN naming and not fixing IP allocation. (3) It sits **above** the freeze check, above nl6#538's resource resolution and above the `isCreatingDevices` / `deviceCreateTotal` / `deviceCreateProgress` stores — a concurrency verdict must not depend on caller data, and a refused request must not clobber the RUNNING batch's counters or clear its freeze-interlock flag (the FR35/FR38 ordering inside the batch is unchanged). (4) The refusal reports the running batch from `createBatch`, a token published by `tryEnterCreateBatch` before the holder proceeds and cleared before its unlock, never from `deviceCreateTotal`/`deviceCreateProgress`: those are written inside the batch and never reset, so reading them stated a FINISHED batch's numbers as fact. `GET /api/v1/status` reports the same token as `create_batch_in_progress` / `create_batch_requested`, which is the poll signal a 409'd client should use — `is_creating_devices` is a proxy that can read false while the gate is held. The `currentIP` rewind is untouched and must stay: the devices have to land on the pre-allocated addresses.

**SCOPE: the gate is batch-versus-batch (and, since nl6#519, batch-versus-profile-reload, the only other holder), and the first draft of this paragraph overstated it.** Three paths still mutate creation state outside it, all pre-existing and none gated here (a separate contract): a previous batch's **detached pre-allocation stragglers** — `prealloc.go`'s 5-minute timeout returns while its workers keep writing `tunInterfacePool`, so a straggler can overwrite the entry for an address the NEXT batch owns, leaking an fd and leaving two links on one IP; **`DeleteAllDevices`**, which clears `deviceIPs` and `tunInterfacePool` mid-walk; and **`Shutdown` / `CleanupPreAllocatedInterfaces`**, which zero `tunPoolSize` and clear the pool. For the same reason `tunPoolSize` / `maxWorkers` last-writer-wins is closed only against a concurrent BATCH, which is what `reservePreAllocBatch`'s comment now says.

**Testing the batch gate needed two production seams**, because the first cut's tests had no detection power: deleting the gate left three of six green, two of them pinning a hand-written MIRROR of the gated body. The seams are `geteuid` (faked in BOTH directions, so the privilege-rejection path is exercised on a root CI container instead of skipping) and `createBatchStageProbe` (nil in production; lets a test stand at a named stage inside a REAL batch, ask whether the gate is held, and abort through the ordinary error return so the deferred release still runs). Every test drives the real `CreateDevicesWithOptions`, and the gate is only observed through `tryEnterCreateBatch`, so a test cannot pass by reaching around a wrapper whose gate is gone. Verified by mutation at 20/20 over 20 runs each. **Still not covered:** a batch driven to COMPLETION, which needs root and a Linux TUN device.

`preAllocProgress` is an **Add-only** `atomic.Int64` (`bumpPreAllocProgress`), with `preAllocProgressBase` published per batch by `beginPreAllocProgress` and `GetStatus` reporting the difference. It was a load-then-store on an `atomic.Value`, which lost updates, AND was zeroed at the top of every batch, which both raced the workers' increments and wiped a concurrent batch's live count. Overlapping batches still share the one gauge, so status reports whichever baseline was published last — a display limit, not a lost count. The type change also removed the `.Load().(int)` assertion, so `GetStatus` no longer panics on a directly-constructed manager that never stored the field, which several test files build.

Pinned by `prealloc_locking_test.go`, which labels each test as a **race-detector pin** (fails only under `-race`) or a **value pin** (fails on an assertion either way). Every concurrency test needs a *spinning* counterpart goroutine with a `running` handshake before the code under test is called: a bounded loop of hand-outs finishes during the batch's own log lines and gives the detector nothing to pair (measured: 3 detections in 40 runs before the reshape, 20 in 20 after).

**Flow status counters (nl6#491).** `sent_packets` / `sent_bytes` / `sent_records` on `GET /api/v1/flows/status` mean **reached the kernel**, and a refused datagram lands in the new `send_failures` instead. Before this they all incremented after a failed `WriteTo`, so the endpoint reported datagrams that never left the host and a down collector was undetectable from it — which is also why nl6#488's datagram gate cannot drive `Tick` through its probe socket (an `EMSGSIZE` never reaches the return value). This aligns flow with syslog, which already counted this way. `flow_sequence` still advances on a failed write, deliberately: reusing the sequence would hide the loss from the collector entirely, whereas advancing shows it as a gap — changing that alters wire semantics and is a separate question.

**Continuous profiling (nl6#635), one gate, off by default.** `profiling.go` + `profiling_api.go` hold the whole feature (two files, three `go.mod` lines, deletable in one commit); the dependencies fork `runtime/pprof` internals and have broken on Go majors, so the Go-bump rule lives in `docs/ops/profiling.md`. `enabled` is THE gate; `server_address` decides whether the SDK also PUSHES. Pull-only exists because the runtime allows ONE CPU profile at a time, so an Alloy CPU scrape needs the push collector off. The gated `/debug/pprof/` surface is mounted on the ROOT router; importing `net/http/pprof` registers on `http.DefaultServeMux` in `init()`, which is inert only because nl6 serves its own router, and that is pinned by an AST scan of every `http.Server` construction.

**Two locks, order `profilingLifecycle` then `profiling.mu`, never the reverse.** `Profiler.Stop` does NOT flush, so the stop closure flushes then stops, bounded and abandoned past the bound. `pushing:true` means the SDK is RUNNING and nothing more: `pyroscope.Start` never touches the network, so a down or unauthorized collector surfaces only through the SDK's logger, counted into `sdk_errors`. **Credentials are FLAG-ONLY, require the flag, and are BOUND to the flag's address**: a REST `server_address` that differs gets none, since otherwise an unauthenticated POST redirects heap profiles plus the operator's Basic auth anywhere. `server_address` is a `*string` with three distinct shapes (omitted, explicit empty, value). **Labels are paid unconditionally** and set once at goroutine birth or via `pprof.Do` at the funnel. **The nesting rule:** `pprof.Do` restores the labels of the context it was GIVEN, so a funnel called with `context.Background()` from a labelled goroutine ERASES that label; funnels take the caller's context, and a redundant relabel is skipped. **The check with detection power is `make test-interop-pyroscope`** against real containers, not the in-package tests. **BREAKING:** the two hand-rolled debug endpoints are gone, replaced by the gated `/debug/pprof/` paths.

The `FlowEncoder` interface has a `MaxRecordSize() int` extension point: fixed-size encoders return 0 (NetFlow5/9, IPFIX), variable-length encoders (sFlow) return a worst-case per-record byte bound that `FlowExporter.Tick` uses for MTU-safe pagination.

**Datagram budget (`flowPayloadBudget`, nl6#485).** Every sizing decision in `Tick` derives from `len(buf)`, so `Tick` reslices the pooled buffer to the collector's payload ceiling once, up front, and the flow loop, the sFlow counters loop and the options encoders all inherit it. The ceiling is the **frame** budget minus headers: `1472` for an IPv4 collector, `1452` for IPv6 (the family is resolved from the collector address, not assumed). The bug this fixes is the reason to keep the distinction sharp: `Tick` used to paginate against a full-MTU 1500-byte buffer, which spent the budget on the UDP *payload* and put NetFlow v9 at 1524 bytes and IPFIX at 1508 bytes on the wire, both fragmented. NetFlow v5 and sFlow escaped only by arithmetic accident (v5's 30-record protocol cap, sFlow's conservative 128-byte worst-case record), not by design, so neither is evidence the budget is right. **Fragmentation is invisible on LOOPBACK (MTU 65536), which is where every Go test sends — that, and only that, is why in-process measurement never caught it. veth DOES fragment** (kernel default MTU 1500), so nl6's own netns→veth path shows the bug plainly; an earlier note here claimed otherwise and made wire verification look like it needed hardware it never needed. `TestFlowDatagramsFitMTU` asserts the frame bound through the real `Tick` path, and a capture over veth confirms it. **Verified on the wire** in an Ubuntu VM (nl6#488): current `main` fragments 0 of 129 datagrams; emulating the pre-fix budget via `-datagram-mtu 1528` reproduces 85 of 212 (40%) with first fragments at exactly 1500 B, matching the original capture. On a link clamped to 1450, the default fragments 64/157 (40%) while `-datagram-mtu 1450` fragments 0/94. The MTU **is** a flag (`-datagram-mtu`) precisely because 1500 is an assumption about an egress path nl6 does not control.

**Flow application ground truth (`scenario-app-traffic`):** flow-protocol scenario reports carry a fleet-wide `applications[]` block — sent-basis `bytes`/`packets`/`records` per `(l4_proto, dst_port)` plus `avg_bytes_per_second` (in-window bytes ÷ window; drain bytes count in totals but never inflate the rate), aggregated at the Tick write-return ledger hook via `scenarioPart.countApps` (set at `installScenPart`; sflow excluded — collector byte math is sampling extrapolation). Shipped `FlowProfile`s floor `SrcPortMin` at 49152 (IANA dynamic range) so random source ports can't collide with collector-side registered-port classification rules, and ICMP records carry zero ports (aggregating under `(icmp, 0)`) — both wire-visible on all flow protocols. See `docs/reference/loadtest-report-schema.md`.

**The scenario post-window phase is a BARRIER, not a duration (nl6#500).** A scenario submit's `drain` is REJECTED with a 400: it never configured anything, and it is the newest member of the accepted-echoed-ignored family. At T1 the terminal gate is published so no new fire initiates, and `finish()` waits for work ALREADY ADMITTED to return from its write. The `drain` ledger bucket and the `drain_end` timestamp stay, because both are OBSERVED, not configured, and the regression stop is BEHAVIOURAL (a reviewer rebuilt the knob under a new name with a name-scanning test green).

**Finalize is bounded, and the uncommon case was bounded first.** nl6#567 bounded the barrier; nl6#618 bounded the joins, which is where a stalled scheduler-driven write actually parked (found by a test that HUNG for five minutes after two reviewers flagged only the ticker joins). **All four waits share ONE budget**, not a ceiling each, because four ceilings would bound finalize at four times the number the operator was told. **Nothing is cancelled**: an abandoned join keeps running and can still move ledger counters after the snapshot, so stragglers are reported as their OWN field and NEVER folded into `dropped`, which would assert an outcome nothing observed. Two races the review caught: `leave()` decrements the shadow AFTER `wg.Done()`, and the ceiling branch prefers a closed `done` because `select` picks at random among ready cases. **60s exceeds `docker stop`'s default 10s grace**, so a container may be SIGKILLed before the ceiling fires.

**Flow emission shape and pacing residency (`jitter-flow-active-timeout`, nl6#462):** the active-timeout deadline carries per-flow jitter of ±`flowActiveJitterFraction` (0.25), drawn **unconditionally** from the device's own `*rand.Rand` inside `GenerateFlows`' batch loop. Unconditional is load-bearing: a branch-dependent draw makes the RNG call count flow-dependent and desynchronises the stream, so a seeded run stops reproducing and `scenario-app-traffic`'s ground truth stops reconciling (`TestFlowJitter_DrawIsUnconditional` guards it; the app-traffic determinism test cannot, since it compares two runs of the same build). **Why jitter at all:** creation is driven by expiry (the cache refills exactly what it lost) and expiry was a deterministic offset from creation, so the creation profile was a pure delay of itself and any irregularity echoed every lifetime forever. Measured autocorrelation at one lifetime fell from +0.96 (GPU) / +0.87 (edge) to +0.17 / +0.23; `TestFlowEmission_EchoIsDamped` asserts it **relative to an undamped baseline it computes itself** via `FlowCache.activeJitterFraction`, not against a threshold, because profiles differ in how much echo they start with (campus is +0.54 undamped, its `DurationMax` sitting on the active timeout so most flows already leave by the self-damping inactive branch).

**The jitter exposed a pre-existing pacing error, and that fix is the load-bearing half.** `effectiveFlowLifetime(fe, sweep)` = `MeanFlowLifetime + sweep/2`: expiry is noticed by a periodic sweep, so a flow's real residency includes the mean wait for it. `flowPacingTarget` / `flowRateReachable` now take the sweep and divide by residency; `installScenPart` passes the SCENARIO's cadence (`scenarioFlowTickInterval`), not the fleet's, because that is what will actually drain the device. Two consequences: the documented per-device ceiling moved 8.5-9.7 → **8.1-9.2 records/s**, and paced runs stopped emitting a few percent low (nl6#462). The term was invisible before the jitter because deterministic deadlines on flows created at sweep boundaries expired at sweep boundaries, so the sweep cost exactly zero. That alignment was an artifact of synthetic timing, not a property of the exporter. **Do not fold the sweep term into `MeanFlowLifetime`** — that is a property of the profile and timeouts, while the sweep is a property of the exporter's cadence, and a scenario may sweep at a different cadence from the fleet.

**SNMPv1 Trap-PDU (nl6#97).** `-trap-snmp-version v1` switches the fleet to the RFC 1157 Trap-PDU. **No catalog schema change, and that was measured before it was designed**: RFC 3584 §3.2 derives every field of the v1 identity from the `snmpTrapOID` the entries already carry, so hand-writing three fields on 23 entries would be 23 chances to disagree with the OID beside them. **A declared `snmpTrapEnterprise` is NOT an override**: RFC 3584 honours it ONLY for a standard trap, so across the shipped corpus the v1 path uses it in ZERO cases. An earlier draft of the spec had this backwards, and READING the RFC rather than recalling it is what caught it. **A v1 PDU carries NONE of the three varbinds v2c prepends.** `SNMPv1Encoder` is PER DEVICE because `agent-addr` is the originator's own IP. **No v1 INFORM** (RFC 1157 defines none), refused at startup and at attach. v2c output is unchanged and that is MEASURED against a digest taken at the baseline commit in a worktree.

**SNMPv3 notifications with USM (nl6#98).** `-trap-snmp-version v3` emits the SAME `0xA7` PDU inside an RFC 3412 ScopedPDU and an RFC 3414 USM envelope, assembled from seams already lifted by nl6#627 rather than re-lifted or duplicated. **The one design decision is that the encoder holds its OWN `*SNMPServer`, and it is not the device's polling server.** In nl6 `SNMPServer` IS the RFC 3411 engine, and a notification originator IS an authoritative engine, so the encoder constructs one private to itself. `usmState()` is UNTOUCHED: its engine ID is fleet-wide by decision, and a one-line edit there would silently re-identify every POLLED device. Because no production poll-path line changed, byte-identity is structural rather than argued.

**The engine ID is derived from the device IP and is deliberately not configurable** (RFC 3411 §5 format 3, with RFC 5612's documentation PEN since nl6 has no PEN and will not claim another vendor's). Derived means DISTINCT, which is the point: two devices sharing a user and password still key differently. A device with no derivable IPv4 is REFUSED at attach rather than falling back to a shared default. **A collector sees TWO different `snmpEngineID` values for one device**, correct per RFC 3414 and documented, because it reads as a defect when debugging. **No SNMPv3 INFORM:** an inform is authoritative at the RECEIVER, so it is refused at three layers with a DIFFERENT message at each. **The load-time datagram budget is measured at the fleet's own wire format**: the first cut dry-rendered v2c while the fire path encoded v3, so a v3 fleet in an 91-byte band disabled nothing, logged nothing and failed at every fire. The test's v2c control is what makes it mean anything.

**Trap operational notes:**
- **`maxTrapPDU` is a FRAME bound, derived, not a literal (nl6#487).** It is `linkMTU - ipv4HeaderBytes - udpHeaderBytes` (1472 at the default MTU), registered in `recomputeDatagramBudgets()` so it tracks `-datagram-mtu`. It was previously a literal 1500 justified as "matches the buffer the legacy path allocated" — the same payload-versus-frame conflation as nl6#485, which put a full-size trap at 1528 B on the wire. **Wire-verified:** an entry sized between the two bounds fragments 40/40 datagrams under the old bound and is refused under the new one. No address-family branch (unlike flow), because trap collectors resolve `udp4` only. Three sites read it and must stay in agreement: the `trapBufPool` allocation, the reference-encoder scratch clamp (both `trap_exporter.go`), and the encode guard (`trap_encode_fast.go`).
- **Two size enforcement points; the load-time one DISABLES rather than rejects.** Catalog load dry-renders each entry (worst-case context INCLUDING a worst-case `{{.Detail}}` and a max request ID — rendering `Detail` empty let a Raise entry pass load and fail at every fire while its Clear was disabled, which can strand an alarm) and marks anything over budget `oversized`: it stays in the catalog but is excluded from BOTH `Pick` and `EntriesByRole`, and is named once at startup. Filtering only `Pick` would leave an oversized `linkDown` firing on every oper-status transition. Loading does NOT fail, because the budget follows an operator-settable MTU — rejecting would make any `-datagram-mtu` below ~1004 refuse to boot on nl6's own shipped optical catalogs, which the operator can fix from neither side. The fire-time encode guard remains the backstop for runtime `{{.Detail}}` and REST `varbindOverrides`, which a load-time render cannot bound.
- **Lowering `-datagram-mtu` disables shipped optical trap entries.** The Ciena `opticalPreFecS[DF]{Raise,Clear}` alarms carry 39 varbinds and encode to 989-1000 B once `{{.Detail}}` and a worst-case request ID are accounted for, so below roughly MTU 1028 they stop firing and are named in the startup log with the size, the gap, and the MTU that would admit them. If optical alarms go quiet after an MTU change, that log line is the answer.
- `TrapSubsystemConfig.PDUBudget` is **required** and passed explicitly by the caller after `SetLinkMTU` has run; a non-positive value is rejected rather than defaulted. The loader does not read the global, so a size check cannot silently run against the default MTU if startup order changes.
- The fire-path resolve/encode error log is `sync.Once`-gated per exporter (`logFirstEncodeErr`), matching `firstWriteErr`. Ungated it was ~1,000 lines/second at 30k devices for a defect present since startup. `sendFailures` still counts every occurrence — only the log line is suppressed.
- INFORM mode (`-trap-mode inform`) requires `-trap-source-per-device=true` (the default) so the per-device UDP socket can demux acks without a global request-id table. Enforced at device-attach time (phase 4 moved it out of startup).
- Pending-inform map is bounded at 100 per device with oldest-drop overflow policy (exposed as `informsDropped` in `GET /api/v1/traps/status`).
- Retransmissions consume global-cap tokens (design decision to prevent retry-storm amplification when the collector is unreachable).
- Collector-side `rp_filter` may need relaxing (`net.ipv4.conf.*.rp_filter=0` or `2`) to accept UDP/162 with 10.42.0.0/16 source IPs — same caveat already documented for flow export.
- Per-device UDP source binding reuses the same `setupVethPair` + `FORWARD -i veth-sim-host -j ACCEPT` iptables rule that flow export already relies on. No new netns / iptables surface.
- **`StopTrapExport` is shutdown-only** (phase-5 review D1). It is not safe to race concurrent device creation: `startDeviceTrapExporter` captures scheduler / pool / encoder pointers under a short RLock and uses them outside that lock, so a concurrent Stop can leave orphan exporters or closed sockets. Today it is only called from the process-exit signal handler. Do not introduce a runtime "restart trap subsystem" control path without first tightening the attach-path lock discipline.

```json
  "hostname": "{{.SysName}}",         // optional override; empty → sysName→DeviceIP fallback
  "structuredData": {                 // 5424 STRUCTURED-DATA; empty map → NILVALUE; dropped in 3164
    "ifIndex": "{{.IfIndex}}",        // keys must match RFC 5424 §6.3.3 SD-NAME grammar
    "ifName":  "{{.IfName}}"
  },
  "template": "Interface {{.IfName}} (ifIndex={{.IfIndex}}) changed state to down"
}
```

**HOSTNAME derivation priority** (resolved at fire time, per design §D5):
1. If the catalog entry defines a non-empty `hostname` template, render it (with the six-field vocabulary) and use the result.
2. Otherwise, use the device's stored `sysName.0` value (captured at device construction).
3. Otherwise, use the device's IPv4 as dotted-quad.

In every branch the result is run through `sanitiseHostname`: spaces become hyphens (spec mandate), other framing / control chars become `_`.

**Syslog transport seam (`add-syslog-tcp`, nl6#92):** `SyslogTransport` (`syslog_transport.go`) sits UNDER the write; catalog resolution, template vocabulary, the scenario gate and ledger accounting stay above it and are transport-independent. `udpTransport` is the datagram path byte-for-byte (including the per-device-bind → shared-pool ladder); `tcpTransport` (`syslog_transport_tcp.go`) is RFC 6587. Same shape as `DialoutTransport`. **TCP is deliberately NOT symmetric with UDP:** it has no shared-socket rung, because one connection carrying several devices multiplexes them into a framed stream with no field to demultiplex on — so a failed connection refuses the attach, and `-syslog-source-per-device=false` makes a TCP attach FAIL rather than degrade. Three things are load-bearing and non-obvious: (1) `SO_SNDBUF` is capped at 16 KiB because Linux auto-tunes to ~4 MiB per connection and this opens one per device (~117 GiB at 30k devices); (2) every write carries a deadline, because the syslog scheduler fires INLINE for the whole fleet so one stalled collector would stop every device; (3) only a read ERROR counts as connection loss — a collector banner would otherwise cause a permanent connect/drop loop. `sent` means "handed to the kernel" on TCP, not "on the wire"; status rows carry `transport` so TCP and UDP devices do not merge. **`maxSyslogMessageBytes = 1400` is a DATAGRAM bound that applies to every catalog regardless of transport** — deliberately, since the check is a once-per-entry dry render at load and making it transport-aware would defer it to a per-device runtime failure.

**Syslog TLS (`add-syslog-tls`, nl6#93):** there is NO `tlsTransport` type — RFC 5425 IS RFC 6587 inside a TLS session, so TLS decorates the DIALER (`syslog_transport_tls.go`) and `tcpTransport` is reused whole. **nl6 is the CLIENT: it verifies the COLLECTOR (`tls.ca_pem` INLINE / system roots / explicit `insecure_skip_verify`) and presents no cert.** The CA is inline PEM, not a path, because the per-device config is REST-settable and a path there is an arbitrary-file-read primitive (CodeQL `go/path-injection`); a path survives only as `-syslog-tls-ca`, read once at startup by `loadSyslogTLSCAFile`. The issue asked which cert to present — that misreads the direction; `sharedTLSCert` is a SERVER identity and is relevant only under mTLS, which is rejected until implemented. **The trap to know:** `dialOnce` caps `SO_SNDBUF` and sets keepalives via `c.(*net.TCPConn)`, which a `*tls.Conn` does not satisfy — so the TLS dialer calls `applySyslogTCPSocketOptions` on the raw socket BEFORE wrapping. Skip that and every TLS device silently inherits Linux's ~4 MiB auto-tuned buffer (~117 GiB at 30k devices). Port defaults to 6514 vs 514, so a bare hostname changes port when the transport changes. TLS record buffers are per connection and ADDITIONAL to the socket buffer, so the plaintext fleet-memory figure does not carry over.

**Syslog operational notes:**
- The format is per-device post-phase-5 — each device's `syslogConfig.Format` sets its own wire format. The shared-socket pool is keyed by `(collector, format)` so 5424 and 3164 streams never interleave on the same socket.
- Per-device UDP source binding reuses the same `setupVethPair` + `FORWARD -i veth-sim-host -j ACCEPT` rule shared by flow / trap. No new netns / iptables surface.
- Per-device bind failure is **non-fatal** for syslog (unlike INFORM): exporter logs a warning and falls back to the shared socket. When the primary per-device write fails but the shared fallback succeeds, the primary failure is logged and stats count the send as successful. If **both** per-device bind and shared-pool open fail, the attach is rejected so `ListDevices` doesn't show a ghost entry.
- The collector-side `rp_filter` caveat is the same as flow / trap — accept UDP from device IPs with `net.ipv4.conf.*.rp_filter=0` or `2`.
- On-demand HTTP fires **bypass the global rate limiter** (test-harness use case; scheduler-driven traffic still honours `-syslog-global-cap`).
- **`StopSyslogExport` is shutdown-only** (phase-5 review D1). Same constraint as trap: `startDeviceSyslogExporter` uses captured pointers outside the short RLock. Only called from the process-exit path today. Tightening is a pre-requisite for any runtime "restart" control plane.

**Syslog HTTP endpoints:**
- `GET /api/v1/syslog/status` — JSON array-of-collectors: `{subsystem_active, collectors: [{collector, format, devices, sent, send_failures}], devices_exporting, rate_limiter_tokens_available?, catalogs_by_type?}`. Same `subsystem_active` semantics as trap. The `(collector, format)` tuple lets devices emit different wire formats to the same collector without interleaving on one socket.

**A handshake is not an Accept (nl6#663).** `tls_handshake_failures` counted `Accept` errors, and gRPC runs `ServerHandshake` AFTER `Accept` returns — so the counter read 0 for every client transport mismatch while `docs/reference/gnmi.md` told operators to read it as exactly that signal. The `Accept` bucket survives as `listener_accept_failures` rather than being deleted, because fd exhaustion at 30k listeners is real. **The reported symptom is a listener that accepts TCP and sends nothing**, which reads as "no gRPC service behind the port" and is not — the diagnosis needs a TLS control dial on the SAME listener, which is why `TestGnmiDialinTLSRejectsPlaintextClient` carries one and why `Clone` must preserve the wrapper. **gNMI optical serving (`/components` branch):** `Resolve` and `ClassifyLeaves` dispatch on `elems[0]` — `interfaces` for the packet surface, `components` for the optical one, everything under the single prefix `/components/component[name=$och]/optical-channel/` (`optical-channel` augments `/components/component`, so one branch suffices). `gnmiOpticalLeaves` is the served contract, classified by container shape: `opticalLeafScalar` (in **both** `config/` and `state/`), `opticalLeafStats` (`state/<leaf>/{instant,avg,min,max}`), `opticalLeafCounter` (`fec-uncorrectable-blocks` — a **bare** leaf; asking for `/instant` on it returns a `NotFound` that says why, because that is the mistake a collector author makes by analogy). **`resourcesCache` is guarded by `resourcesCacheMu` (nl6#555).** `LoadSpecificResources` runs on the `net/http` handler goroutine via `resolveCreateResources`, so two concurrent `POST /api/v1/devices` naming different device types were a concurrent map write — which the runtime answers with `throw()`, past any `recover()`, killing the whole simulator rather than one request. **The canonical locking rule lives in the `resourcesCache` comment in `types.go`** — which operations the lock covers, why it is not held across the load, and why an `RWMutex` rather than a `sync.Map` or `sm.mu`. Do not restate it here; the two copies had already diverged once. Two points that are not in that comment: **there are TWO write sites**, because a device type shipped as a directory publishes from `loadSpecificResourcesFromDir` while a legacy single-file type publishes from `LoadSpecificResources` itself, and a test suite that writes only directory fixtures leaves the single-file lock pinned by nothing; and a rejection is still **not** cached, deliberately, so a type stays re-triable once the operator fixes the file (the nl6#538 classification is untouched). Pinned under `-race` by `resources_cache_race_test.go`, which covers both layouts plus a mixed row. Without the lock that test reports a data race **deterministically under `-race`** and a `fatal error: concurrent map writes` on most but not all runs without it — the runtime's concurrent-write detection is best-effort, the race detector is not. **Reload is EVICTION, never mutation (nl6#519).** `POST /api/v1/resources/reload` drops cache entries so the NEXT device creation reads from disk. **No code path may write into a `*DeviceResources` a device may hold**: a device holds the pointer and serves from indexes built ON that struct, so a device created before a reload serves exactly what it served before. The response says so (`evicted`, `devices_on_old_snapshot`, `present_on_disk`, a `note`), because a caller must not be able to believe existing devices changed. `devices_on_old_snapshot` is counted per KEY, not per evicted pointer, since a device from two generations back is also on a pre-reload snapshot and a pointer comparison under-counts it.

**`sm.deviceResources` is NOT compiled-in.** `loadDefaultResources` reads `resources/asr9k/` from disk THROUGH the cache, so the whole auto-start fleet's profile is reloadable; the compiled-in constants are the fallback only when no asr9k profile exists, and that path stays out of the cache. **It holds `createBatchGate`, and that is what makes it correct rather than race-free**: `publishResources` keeps the FIRST entry when it re-checks under the write lock, so an evict racing an in-flight load would clear the slot and watch that load re-publish the OLD contents. It takes the gate DIRECTLY and publishes its OWN token, so a colliding create is told a RELOAD holds the gate rather than being given a batch's IP-cursor remedy. Name validation runs BEFORE the gate, so a malformed name is 400 rather than 409. **Trap and syslog catalogs are OUT OF SCOPE by decision**, and the note says a catalog edit still needs a restart so that a 200 is not the accepted-echoed-ignored family. No file watcher.

### Key design decisions

- **sync.Map for OID lookups** — lock-free O(1) access during concurrent SNMP queries
- **Pre-computed next-OID mappings** — efficient SNMP GETNEXT/WALK without scanning
- **Buffer pool** — reduces GC pressure on SNMP request handling
- **Shared SSH/TLS keys** across all devices — avoids per-device key generation overhead
- **Network namespace isolation** (`nl6sim` namespace) — prevents systemd-networkd interference
- **Per-device flow egress** — `setupVethPair` installs a `FORWARD -i veth-sim-host -j ACCEPT` iptables rule so that per-device flow exporters can send UDP out of the ns through the host's routing table (Docker-present hosts default FORWARD to drop). Rule is removed in `NetNamespace.Close`. The simulator image includes `iptables` for this reason. On the downstream flow collector, `rp_filter` may need to be relaxed (`net.ipv4.conf.*.rp_filter=0` or `2`) to accept packets with 10.42.0.0/16 source IPs.

### Device types

29 device types across 9 categories: Core Routers, Edge Routers, Data Center Switches, Campus Switches, Firewalls, Servers, GPU Servers (NVIDIA DGX-A100/H100/HGX-H200), Storage Systems (AWS S3, Pure Storage, NetApp ONTAP, Dell EMC Unity), Optical Transport (Ciena Waveserver 5).

**Optical value engine (`optical_cycler.go`):** `OpticalCycler.GetDynamicAt(component, leaf, t)` is the single dispatcher for every coherent-optical leaf, keyed by **OCH component name** (never `ifIndex`). Same contract as `IfCounterCycler`: pure function of elapsed time, no per-channel goroutine, immutable after publish, single-init panic guard, per-channel jitter over a **sorted** channel slice (seed salt `^0x4F43_0000`). **Two independent dials** — received power `pIn` and accumulated noise `nAse`, with `osnr = pIn − nAse` in dB — because a single power dial makes OSNR perfectly correlated with power and leaves the *attenuation* (low power / normal OSNR) and *ASE* (normal power / low OSNR) quadrants unreachable. Cascade: `osnr → q-value → pre-fec-ber` (`½·erfc`, monotonic — the erfc tail is **shallow** at the 2e-2 SD-FEC threshold, ~3× per 2 dB, so decade-scale assertions there are wrong physics) `→ fec-uncorrectable-blocks`. Off-spine leaves (`output-power`, `target-output-power`, `laser-bias-current`, `chromatic-dispersion`, `polarization-mode-dispersion`, `polarization-dependent-loss`, `frequency`, `operational-mode`, `line-port`) read none of the receive dials — that flatness *is* the fibre-vs-transponder diagnostic. Both dials share a period so their difference collapses exactly to one sinusoid, making the above-threshold integral behind the block counter closed-form, O(1) and monotonic by construction. Types come from the **pinned OpenConfig revision** (terminal-device 2026-01-14 + platform-transceiver 2026-03-25), which governs over Ciena's native model: statistics leaves at `fraction-digits 2`, `pre-fec-ber` at `fraction-digits 18`, `fec-uncorrectable-blocks` a bare `uint64` counter with **no** stats container. **`post-fec-ber` is not served** — OpenConfig defines it but Ciena removed it, so a collector rule keyed on it would never fire against real hardware. `-optical-scenario` / per-device `optical_scenario` selects the health band via `opticalBandFor`; only `failing` crosses the FEC threshold. **Band boundaries are sized against the jitter envelope, not the nominal point:** each dial mean is jittered ±`opticalMeanJitterDB`, so the OSNR mean — their *difference* — spreads over ±2× that, stacked on top of the OSNR sine amplitude (≤ `1.1×(pInAmp+nAseAmp)` in antiphase). The tier contracts (`degraded` never accrues uncorrectable blocks, `failing` always does) must hold for every channel of every seed, so changing any mean, amplitude, or the jitter constant invalidates the arithmetic documented at `opticalBandFor` — `TestOpticalBandContractsHoldAcrossSeeds` sweeps seeds because a single-seed test passes while a fleet-sized share of channels violates the contract. **Capability symmetry with flow:** a non-clean `optical_scenario` on a type with no OCH inventory is rejected **400** (`opticalIncapableRequest`, the inverse mirror of `flowIncapableRequest`), and `opticalScenarioFieldFor` omits the field from `GET /api/v1/devices` for non-optical types rather than reporting a knob that does nothing.

**On-demand optical degradation (`optical_degrade.go`, `optical_api.go`):** `POST /api/v1/devices/{ip}/optical/{component}/degrade` with `input_power_drop_db` / `noise_rise_db` / optional `duration` (24h cap; neither offset = clear). Two knobs, not one severity dial — they select the diagnostic quadrant (attenuation: power down, **OSNR unchanged** — the sag hits `pInAt` AND `nAseAt`, because signal and accumulated ASE traverse the same fibre, so it cancels out of `osnr = pIn − nAse`; ASE: power held, OSNR down). Crossing the FEC threshold therefore requires `noise_rise_db`, which is the discrimination collector rules key on and the reason the engine has two dials. **Degradation is an append-only list of immutable `opticalEpisode`s** (`atomic.Pointer[[]opticalEpisode]` per channel, copy-on-append), NOT an install-and-clear pointer: `fec-uncorrectable-blocks` is the time integral of an above-threshold indicator over `[0,t]`, so clearing a "current sag" would remove already-elapsed degradation from the integral and make the counter **decrease** — a collector reads that as a device reboot. Two load-bearing invariants: a published episode's window is frozen (past segments can never change → monotonic by construction), and `t0` is never in the past (no already-observable value is rewritten; a backdated request clamps forward). The one permitted mutation is truncating an *open* episode's end forward to `now` when a later POST supersedes it. `aboveThresholdSeconds` is therefore **piecewise**: the OSNR mean steps at episode boundaries, so the interval splits there and the same closed-form arcsine applies per segment (cost O(boundaries), not O(t); an undegraded channel takes the original single-segment path). The sag is applied in `pInAt`, `nAseAt` **and `osnrAt`** — `osnrAt` reads the precomputed phasor, so sagging `pInAt` alone would move the input-power leaf while leaving the whole cascade untouched. **No revert timer** (deviation from the story's letter, contract preserved): an episode carries its own end and the engine is a pure function of `t`, so the revert is arithmetic — nothing to schedule, cancel, or leak, unlike the interface-state convention which must put mutated state back.

**gNMI decimal values:** `resolvedUpdate.Value` gained `gnmiDecimal{val, digits}` — a distinct type, not a pre-formatted string, because JSON_IETF needs an RFC 7951 quoted decimal while PROTO needs `double_val`; a Go `string` would silently take the `string_val` branch and corrupt an advertised encoding. At 18 fraction digits `double_val` is lossy (inherent to decimal64 in gNMI's PROTO scalar set); JSON_IETF preserves the digits.

**Per-device-type protocol capability.** Device types are not uniformly capable. `ciena_waveserver5` is a layer-1 coherent optical transport platform: it performs no L3/L4 inspection and therefore **exports no flow records**. Absence has to be *implemented*, not omitted — `GetFlowProfile` (`flow_profiles.go`) falls back to `flowProfileEdgeRouter` for any type absent from `flowProfileMap`, so leaving a type out would silently give it edge-router flow ground truth. The explicit marker is `flowIncapableTypes` + `SupportsFlowExport`, consulted at both device-creation paths; a batch-wide flow seed **skips** incapable devices with a log line (so `-flow-collector` stays usable with `-round-robin`), while a request whose entire resolved type set is incapable is rejected with **400** (`flowIncapableRequest`). Its optical inventory is keyed by OCH **component name** (`OCH-1-1`) in an `optical` resource part, never by `ifIndex`; `validateOpticalInventory` fails the load loudly if that part is missing, malformed, or disagrees with `OpticalProfile.ChannelCount`, because the resource decoder is not strict and would otherwise discard it silently.

**Capability-gating boundary (#364):** GROUND-TRUTH-BEARING surfaces — things a collector validates against (flow byte math, optical values) — get per-type fidelity gating (`flowIncapableTypes`, `opticalIncapableRequest`). TRANSPORT PLUMBING deliberately does not: gNMI dial-out is Arista-flavored `gnmireverse` on a fleet with zero Arista types, because its purpose is letting teams test a dial-out collector at scale against a heterogeneous fleet — gating it by fidelity would gate it to the empty set. The absence of dial-out gating is a decision, not an omission. Completeness of the flow maps is enforced in CI (`TestFlowCapabilityCompleteness`: every repo type in `flowProfileMap` XOR `flowIncapableTypes`); operator-supplied custom resource files fall back to the edge-router flow profile with a once-per-type log line, since the compiled-in maps are unreachable to them.

Each device type has resource files under `resources/<device-type>/` containing JSON for SNMP OID responses, SSH command responses, and REST API responses.

## Source file headers

This repo is a fork of `saichler/l8opensim`. Header policy depends on whether a source file is **forked** (basename exists in `go/simulator/*.go` upstream) or **new** (created in this fork):

- **Forked files** keep upstream's full Apache 2.0 boilerplate header verbatim. Do not replace, trim, or modify it — Apache 2.0 §4(c) requires the original copyright notice be preserved when redistributing.
- **New files** (every file in `go/nl6/` whose basename has no upstream counterpart) get the canonical SPDX-short header, no exceptions:

  ```go
  /*
   * Copyright <YEAR> Ronny Trommer <ronny@no42.org>
   * SPDX-License-Identifier: Apache-2.0
   */
  ```

  - `<YEAR>` = file's creation year. Do not bump it on every edit.
  - Email in angle brackets (`<…>`), not parens — REUSE/SPDX scanner convention.
  - **No `Created by` line.** Authorship lives in `git log`, not in headers — it goes stale and conflates authorship (factual) with copyright (legal).
  - Header sits at the very top of the file, with one blank line between the closing `*/` and the next non-blank line (`//go:build` directive, `package` clause, or a leading comment block).
