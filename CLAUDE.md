## Architecture

**nl6** is a Go-based network device simulator capable of running 30,000+ concurrent simulated devices, each responding to SNMP (v2c/v3), SSH, and HTTPS REST protocols. It uses Linux TUN interfaces and network namespaces to give each device its own IP address.

### Package layout

| Path | Purpose |
|------|---------|
| `go/nl6/` | Core simulator — all device simulation logic and tests |
| `go/nl6/resources/` | 389 JSON files (29 device types) with SNMP/SSH/REST response data |

### Core simulator components (`go/nl6/`)

**Device lifecycle:** `simulator.go` (CLI/entry) → `manager.go` (SimulatorManager, shared keys/certs) → `device.go` (per-device startup, protocol server lifecycle)

**SNMP stack:** `snmp_server.go` → `snmp.go` (request handling) → `snmp_handlers.go` (OID lookup via sync.Map) → `snmp_response.go` (response building) → `snmp_encoding.go` (ASN.1 BER/DER).

**SNMP response size (nl6#489).** `maxSNMPResponseSize` is a FRAME bound derived from `linkMTU` and refreshed by `recomputeDatagramBudgets`, so it tracks `-datagram-mtu`; udp4 only, no address-family branch. **GETBULK truncates** (RFC 3416 §4.2.3 — a walk resumes from the last OID returned) but **GET returns `tooBig` with an empty binding list** (§4.2.1 — the requester has no resume point, so a partial answer is an undetectable wrong answer). Both PDU types share `createVarbindResponse`, deliberately (nl6#176: Enlinkd bundles three lldp OIDs in one GET), so the rule is an explicit `snmpOverflowRule` argument rather than something the encoder infers — getting it backwards is the most damaging mistake available here. Sizing is exact and incremental via `snmpMessageSizeFor`, never estimated: every bug in this family was a predicted size disagreeing with an emitted one. The GETBULK **walk** is separately clamped by `minVarbindSize` — a CPU guard, not a correctness one (a walk step is expensive; ~29 req/s already saturates cores on the LLDP path), deliberately an under-estimate so it never under-fills. **SNMPv3 GETBULK is NOT bounded** — separate encoder, hardcoded `max-repetitions` of 10, so an oversized v3 response is unreachable by accident rather than by design; honouring a real value there needs the bound first. `max-repetitions` is honoured at any width on the v2c path: the old parser read single-byte BER content only, so anything ≥ 128 silently became 10 — **benchmark numbers taken above 127 before this change are not comparable with numbers after it.** SNMPv3 is handled separately in `snmpv3.go` + `snmpv3_crypto.go` (MD5/SHA1 auth, DES/AES128 privacy).

**SNMP exceptions and SNMPv1 (nl6#517).** An OID absent from a profile is answered with the RFC 3416 `noSuchObject` exception (`80 00`), never `noSuchInstance` (a flat OID→value map cannot evaluate the prefix-registration test that separates them) and never a string. The exceptions travel from lookup to encoder as **sentinel strings** (`valueNoSuchObject`, `valueEndOfMibView`; `isSNMPExceptionValue`) that `encodeTypedValue` turns into tags — a value-space hazard (a resource value literally `noSuchObject` would encode as an exception; a v1 manager gets `noSuchName`) — see the resource value guard below. **SNMPv1 has no exceptions**, so both response builders divert a sentinel to `error-status = noSuchName` with `error-index` at the first offending binding and the request's names echoed with NULL values (RFC 3584 §4.2.2.2.1 noSuchObject, §4.2.2.2.2 endOfMibView). That diversion is **GET-only** in `createVarbindResponse` (`rule == overflowTooBig`): GETBULK does not exist in v1, and its `oids` are walked, not requested, so echoing them would be neither the RFC 1157 echo nor bounded. The GET echo deliberately skips the `snmpMessageSizeFor` budget — it is byte-for-byte the request's own varbind list, which the socket already accepted, and sizing it would produce a partial `noSuchName` echo. **SNMPv3 GET/GETNEXT go through `encodeTypedValue` too** (nl6#518): `createScopedPDU` is its third caller, so v3 carries the same tags as v2c and shares the value-space hazard. **v3 GETBULK never emits `endOfMibView`**: `handleSNMPv3GetBulk` breaks on the sentinel before encoding and, with nothing collected, answers a placeholder `sysDescr.0 = "No data"` binding whose OID sorts before the request, so a GETBULK-driven v3 walk still does not terminate on the exception (pre-existing, listed in deferred-work.md).

**Counter64 under SNMPv1 (nl6#524).** Counter64 does not exist in v1, and `encodeTypedValue` picks the tag from the OID alone, so a v1 GET of an `ifHC*` column used to answer tag `0x46` under `error-status = noError`. RFC 3584 §4.2.2.1 prescribes **two different behaviours, and the asymmetry is the whole design**: a **GET** diverts to `noSuchName` (same one-pass loop in `createVarbindResponse` as the sentinel diversion, so the FIRST offending binding wins whichever kind of offence it is), while a **GETNEXT SKIPS** the object and continues to the next successor, in `handleSNMPv2cRequest`. A GETNEXT names a position rather than an object, so erroring there would stop a v1 walk dead at the first HC column and truncate the table with no signal. `createSNMPResponse` must therefore NOT gain the diversion. Two properties worth keeping: the test is on the OID's DECLARED type, not on what the value encodes as (a Counter64 column holding a non-numeric value used to go out as a legal-in-v1 OCTET STRING and still diverts, because the MIB type is what a v1 manager cannot represent); and the GETNEXT path takes ONE `lldpServedOIDs()` snapshot for the first step AND the skip run, reused via `findNextOIDWithServed`, because calling `findNextOID` in a loop rebuilds the device's whole LLDP/ifAlias view per step (and two snapshots could straddle a topology generation bump). Walk order is column-major, so the Counter64 block is one contiguous run of (8 HC columns × interfaces), measured at **288 steps** on the widest shipped profile, skipped once per walk. The VERSION test comes first and is free (the request is already parsed at the top of `handleSNMPv2cRequest`), so a v2c fleet short-circuits on one integer compare and never reaches `snmpTypeTag`, which is a linear scan of the ~50-row type table that concatenates a string per row. Reversing those two operands would put that scan on every GETNEXT of every version. The skip loop is bounded twice (a non-advancing successor ends the walk, plus a step cap that backs up the comparison itself) because it runs INLINE in the shared UDP handler with no `recover()`: before this change a non-advancing `oidNextMap` was only the manager's problem, now it would wedge every device. Either bound is a data defect, logged once per device (`logFirstSkipAbort`, same gate as the trap path's `logFirstEncodeErr`) and answered as end-of-MIB, and `TestV1GetNextSkipLoopTerminatesOnNonAdvancingMap` pins both bounds by corrupting `oidNextMap` under a deadline. **Coverage is bounded by `oidTypeTable`** (the eight `ifXTable` HC columns); a 64-bit counter served under any other OID still reaches v1 as `0x46`. v1 GETBULK is deliberately untouched, for the same reason the sentinel diversion leaves it alone. Pinned by mutation rather than assertion alone: `TestV1WalkNeverReturnsCounter64` requires the walk to REACH the far side of the HC run, because absence of `0x46` is also satisfied by a walk that stopped at it, and four mutations are verified to fail the suite: removing the GET divert, removing the `rule == overflowTooBig` GETBULK guard, swapping the two behaviours, and over-skipping past the first non-Counter64 successor.

**SNMP resource value guard (nl6#523).** `validateSNMPResourceValues` (`resources.go`, beside `validateOpticalInventory`) rejects a resource response for which `isSNMPExceptionValue` is true, naming the file, the OID and the value. The test is EXACT, so `noSuchObject seen` and `NoSuchObject` are data; the error also says that omitting the entry is how you make an OID answer `noSuchObject` on purpose, since an absent OID already does. Scope is the `snmp` array only: SSH/API/Optical entries never reach `encodeTypedValue`, and the trap/syslog catalogs use a different encoder. Wired at the **four loaders a resource file can reach**. `createDefaultResources` writes compiled-in constants and is deliberately not guarded, since no input could make that check fire. Validated per JSON *part* in the two directory loaders, since a device-type directory holds ~15 split files and a post-merge check would name only the directory. `TestGuardIsWiredIntoLoaders` fails if any of the four calls is deleted (mutation-verified, with a positive control per loader asserting the fixture's exact entry count, so an unconditionally-erroring loader or one that dropped a part on merge could not pass). `TestSentinelValueWouldReachTheWireAsAnException` pins the sentinel set from the ENCODER side with literal strings and tags, so a third sentinel added to `encodeTypedValue` alone fails it. It is a refusal rather than the trap catalog's disable-and-warn because the rule depends on no operator-settable knob and the whole shipped set passes (`TestShippedResourcesLoadClean`, every `resources/` directory except the `_`-prefixed ones, asserting a non-zero entry count). **Three caveats before calling it a refusal:** it fires on `LoadSpecificResources`, so a bad operator file is also a failed REST device-creation call mid-run (surfaced as HTTP 500, where this repo's convention for caller-data faults is 400. Deferred, since it needs a wrapped error to classify on); at two sites a rejection is DOWNGRADED to a log line (`simulator.go`'s startup load falls back to the `cisco_ios` profile, `device.go`'s round-robin skips the offending type); and it closes the **resource-file** route only. `sysName`/`sysLocation` are served outside the resource map, `sysLocation` coming from the operator-supplied worldcities CSV, and are not covered. Scope is one rule deliberately: the OID-typed VALUE guard on the same surface remains open under **nl6#529**, though the encoder half of that issue has since landed (see the OID sub-identifier paragraph below). Still open from nl6#529 besides the guard: the value-slot OCTET STRING fallback (`encodeTypedValue`'s OID branch still emits `06 00` for an unparseable value), and the trap catalog loader's `validateDottedOID` not consulting `legalOIDArcPair`. Nothing in the sentinel guard touches an encoder, so no wire behaviour changed for any input that loads today.

**SNMP test helpers are split by build tag, deliberately.** Three test files carry `//go:build linux` (`snmp_getbulk_test.go`, `snmp_response_size_test.go`, `datagram_mtu_gate_linux_test.go`); the other 143 are untagged and run on macOS. A helper defined in a tagged file is therefore invisible to the untagged suites and is only ever exercised in CI. That is how the exception suite ended up with its own copy of the server constructor (nl6#525). **Shared SNMP test helpers go in the untagged `snmp_testutil_test.go`**, which is where `newTestServer` and `v3TestServer` live. To typecheck the tagged half from macOS without a Linux box: `make lint` (its `ANALYSIS_ENV` sets `CGO_ENABLED=0 GOOS=linux`), or directly `cd go && CGO_ENABLED=0 GOOS=linux go vet ./nl6/`. Plain `GOOS=linux go vet` fails: cgo picks the macOS SDK and `linux_syscall.c` breaks on `setresuid`. Real execution still needs Linux.

**OID first sub-identifier is a varint, on BOTH sides (nl6#529).** X.690 §8.19.4 packs the first two arcs into ONE sub-identifier valued `40*first + second`, encoded as a base-128 varint like every other one. `encodeOID` emitted it as a single byte and `decodeOID` read it back as one (`/40`, `%40`): symmetric, and both wrong. The round-trip held **only while the second arc stayed under 40** and fabricated silently above it — `3.40.1` went out as `.4.0.1`, `2.87.1` as `.4.7.1`, `2.175.1` as `.6.15.1`, and the legal ITU arc `2.999` as `.1.15`. Valid-looking BER carrying data nobody wrote, which is worse than invalid BER because a collector accepts it. Both sides now use the varint (`encodeOIDComponent` already emitted one correctly, so the encode fix was a one-line substitution), and `2.999`-class OIDs became expressible. **The measured constraint was `second <= 39`, not 127 and not 255** — both of those were proposed from hand arithmetic during nl6#523 and both were wrong, because the binding limit was the decoder's `%40`, not any varint ceiling. `legalOIDArcPair` is the single definition of a representable pair: first arc 0..2, second arc 0..39 when first < 2 (a wider one would ALIAS a higher first arc, since `1.40` and `2.0` both compute 80), and the COMBINED value within 2^32-1 — the combined value, because bounding the raw second arc instead is exactly how the two encoders diverged on `2.7000000000`. `encodeOID` and `appendOID` no longer swallow `strconv` errors either; that was the second route into the same fabrication (`1.3.x.7` → `.1.3.0.7`, `1.` → `.1.0`). `decodeOID` additionally refuses an unterminated varint (previously read at face value: `{0x2b, 0xff}` → `.1.3.127`), one that overflows (previously wrapped to the arc **-1**) and a non-minimal one with a leading `0x80` (X.690 §8.19.2, otherwise unbounded distinct byte strings decode to one OID); it parses attacker-supplied request bytes at three sites, so it refuses malformed input rather than inventing a value. **Pinned by a PROPERTY test and a fuzz target, not a table** (`snmp_oid_roundtrip_test.go`): `decodeOID(encodeOID(x))` equals the canonical spelling of `x` over ~11,500 generated OIDs, and `FuzzOIDRoundTrip` additionally asserts `encodeOID == appendOID` on arbitrary input. That fuzzer found the `2.7000000000` divergence and the over-strong property statement (leading zeros are a different spelling, not a fabrication); both are committed as seeds. Parity between the two encoders is **necessary and not sufficient** — during nl6#523 both were changed together and their parity test stayed green over a fabricated OID. Every shipped OID encodes byte-identically to before: `TestShippedOIDsUnchangedOnTheWire` pins a SHA-256 of 5,676 distinct OIDs paired with their encodings, and that digest was computed against `main@09546c3` BEFORE the change, not re-derived from the new code (a draft of this test did the latter while the docs claimed a comparison, which proves nothing). The corpus takes OID-typed VALUES as well as names, and decides which values are OIDs via `snmpTypeTag` on the sibling `oid` key rather than by string shape, because an IPv4 address in an `ipAdEntAddr` response is digits and dots too and never reaches `encodeOID`. **Independent conformance** is `TestOIDEncodingMatchesEncodingASN1`, comparing against Go's `encoding/asn1`: it is the only check here that is not nl6 verifying nl6, and it is the shape that would have caught the original defect, since every round-trip and parity test in the package passed while both functions disagreed with X.690 in the same direction.

**SNMP parser totality.** The request path is a hand-written BER parser, and every device answers from one process — a panic there unwinds the listener goroutine and drops the whole fleet mid-run, so the parsers are required to be TOTAL (a value or an error for any input, never a panic). There is deliberately **no `recover()`** on the request path: it would turn a parser defect into a silently dropped datagram, indistinguishable from a network drop. The guarantee is held by the fuzz targets in `snmp_parser_robustness_test.go`, each seeded with the input that crashed it, and `go test` replays every seed on an ordinary run so a regression fails the normal suite. **Coverage is partial and the gap is known:** six parsers are fuzzed there (`getPDUType`, `parseIncomingRequest`, `parseAllOIDsFromRequest`, `isSNMPv3Request`, `parseSNMPv3Message`, `extractOIDAndTypeFromScopedPDU`), plus `decodeOID` by `FuzzDecodeOID` in `snmp_oid_roundtrip_test.go` — 5 of the package's 56 `parseLength`/`skipLength` call sites, with `snmp_handlers.go` (17 sites) and `trap_v2c.go` (6, and attacker-reachable via INFORM acks) never fuzzed at all. Totality is therefore a requirement on the whole family that has been VERIFIED for six of them; sizing the rest is nl6#513, and its outcome also decides the no-`recover()` position above. Two traps, both of which produced live crashes: (1) **`parseLength` signals failure with `-1`, and `-1` passes an upper-bound check** — `pos+n > len(buf)` is false for `n == -1`, so the guard admits it and the following slice panics on an inverted range; every length check needs the `n < 0` arm too. (2) **A short-circuiting guard does not short-circuit its own error message** — `if pos >= len(data) || data[pos] != tag { return fmt.Errorf("got 0x%02X", data[pos]) }` evaluates `data[pos]` whenever the branch is taken, including on the exact out-of-range case the check exists to catch. Separately, **SNMPv3 privacy key derivation divides by zero on an empty password** (RFC 3414 §A.2 repeats the password to fill a 1 MB buffer); the config is REST-settable, so `SNMPv3Config.Validate` rejects it **400** at device creation, and the generators return `nil` rather than a zero-filled key — `aes.NewCipher`/`des.NewCipher` reject nil with a `KeySizeError` callers already handle, whereas a right-length all-zero key would encrypt successfully under a key nobody configured.

**Dynamic IF-MIB counters (`if_counters.go`):** `IfCounterCycler.GetDynamic` serves every per-interface counter under `ifTable` (`.1.3.6.1.2.1.2.2.1`) and `ifXTable` (`.1.3.6.1.2.1.31.1.1.1`) analytically — no per-interface goroutine. `ifHCInOctets` / `ifHCOutOctets` are the master dial (sine wave, 60–100 % of `ifSpeed`, 1 h period); HC packet counters (ucast / mcast / bcast) derive from octets ÷ jittered packet size × jittered ratios; Counter32 shadow columns (`ifInUcastPkts`, `ifInMulticastPkts`, etc.) return the low 32 bits of the matching Counter64 HC column; error / discard counters derive from per-device ppm bands set by the `IfErrorScenario` field (`clean` | `typical` | `degraded` | `failing`). The same dispatcher powers the sFlow `counter_sample` body path in `counter_source.go`, so SNMP and sFlow values agree byte-for-byte at the same instant.

**Interface state engine (`interface_state.go`, added by add-interface-state):** `IfCounterCycler` owns an `InterfaceState` per device that stores `oper-status` / `admin-status` / `last-change` per ifIndex in a packed `atomic.Uint64` slot (3 bits + 3 bits + 58 bits wall-relative ns). `ifAdminStatus.<N>` (`.7`), `ifOperStatus.<N>` (`.8`), `ifLastChange.<N>` (`.9`) are now claimed by the cycler — `GetDynamicAt` reads them from the state engine, so SNMP and gNMI agree byte-for-byte at the same instant. Mutators are `SetOperStatus` / `SetAdminStatus` (CAS-loop, idempotent on no-op), fed by two sources: the flap scheduler (`flap_scheduler.go`, single shared min-heap goroutine driving Poisson-distributed flaps per (device, ifIndex) — same shape as `trap_scheduler.go`) and the REST control plane (`POST /api/v1/devices/{ip}/interfaces/{ifIndex}/{oper,admin}-status`). State transitions broadcast a `StateChange` event to every registered ON_CHANGE Subscribe listener via a per-stream depth-16 channel with drop-oldest on overflow. Cross-protocol consistency in Tier B: SNMP, gNMI Get, and gNMI Subscribe ON_CHANGE all see the same value at the same instant. **Tier C (`correlate-state-notifications`):** an oper-status transition now also fires correlated link traps + syslog for that ifIndex — `InterfaceState.SetNotify` installs an `atomic.Pointer[func(StateChange)]` hook invoked (oper-only, gated on `LeafOperStatus`) at the end of `Broadcast`, after the slot store commits. The manager wires it at trap/syslog attach time (`wireStateNotify`) to call `FireForInterface(entry, ifIndex)` on the role-matched catalog entries (`EntriesByRole`, vendor-wins-per-role); the closure snapshots the exporters under `device.mu.RLock` and fires outside the lock (closing-guard handles teardown). Covers all three mutation sources (REST, flap scheduler, REST auto-revert) via the single `Broadcast` funnel. Link telemetry volume now rides real state changes (`-if-flap-scenario` / REST), and state-driven fires bypass the Poisson global cap on initial transmit.

**REST auto-revert convention.** `POST .../oper-status` and `POST .../admin-status` accept an optional `duration` field (`{"status":"DOWN","duration":"30s"}`). **Flow status counters (nl6#491).** `sent_packets` / `sent_bytes` / `sent_records` on `GET /api/v1/flows/status` mean **reached the kernel**, and a refused datagram lands in the new `send_failures` instead. The `FlowEncoder` interface has a `MaxRecordSize() int` extension point: fixed-size encoders return 0 (NetFlow5/9, IPFIX), variable-length encoders (sFlow) return a worst-case per-record byte bound that `FlowExporter.Tick` uses for MTU-safe pagination.

**Datagram budget (`flowPayloadBudget`, nl6#485).** Every sizing decision in `Tick` derives from `len(buf)`, so `Tick` reslices the pooled buffer to the collector's payload ceiling once, up front, and the flow loop, the sFlow counters loop and the options encoders all inherit it. The ceiling is the **frame** budget minus headers: `1472` for an IPv4 collector, `1452` for IPv6 (the family is resolved from the collector address, not assumed). The bug this fixes is the reason to keep the distinction sharp: `Tick` used to paginate against a full-MTU 1500-byte buffer, which spent the budget on the UDP *payload* and put NetFlow v9 at 1524 bytes and IPFIX at 1508 bytes on the wire, both fragmented. NetFlow v5 and sFlow escaped only by arithmetic accident (v5's 30-record protocol cap, sFlow's conservative 128-byte worst-case record), not by design, so neither is evidence the budget is right. **Fragmentation is invisible on LOOPBACK (MTU 65536), which is where every Go test sends — that, and only that, is why in-process measurement never caught it. veth DOES fragment** (kernel default MTU 1500), so nl6's own netns→veth path shows the bug plainly; an earlier note here claimed otherwise and made wire verification look like it needed hardware it never needed. `TestFlowDatagramsFitMTU` asserts the frame bound through the real `Tick` path, and a capture over veth confirms it. **Verified on the wire** in an Ubuntu VM (nl6#488): current `main` fragments 0 of 129 datagrams; emulating the pre-fix budget via `-datagram-mtu 1528` reproduces 85 of 212 (40%) with first fragments at exactly 1500 B, matching the original capture. On a link clamped to 1450, the default fragments 64/157 (40%) while `-datagram-mtu 1450` fragments 0/94. The MTU **is** a flag (`-datagram-mtu`) precisely because 1500 is an assumption about an egress path nl6 does not control.

**Flow application ground truth (`scenario-app-traffic`):** flow-protocol scenario reports carry a fleet-wide `applications[]` block — sent-basis `bytes`/`packets`/`records` per `(l4_proto, dst_port)` plus `avg_bytes_per_second` (in-window bytes ÷ window; drain bytes count in totals but never inflate the rate), aggregated at the Tick write-return ledger hook via `scenarioPart.countApps` (set at `installScenPart`; sflow excluded — collector byte math is sampling extrapolation). Shipped `FlowProfile`s floor `SrcPortMin` at 49152 (IANA dynamic range) so random source ports can't collide with collector-side registered-port classification rules, and ICMP records carry zero ports (aggregating under `(icmp, 0)`) — both wire-visible on all flow protocols. See `docs/reference/loadtest-report-schema.md`.

**Flow emission shape and pacing residency (`jitter-flow-active-timeout`, nl6#462):** the active-timeout deadline carries per-flow jitter of ±`flowActiveJitterFraction` (0.25), drawn **unconditionally** from the device's own `*rand.Rand` inside `GenerateFlows`' batch loop. Unconditional is load-bearing: a branch-dependent draw makes the RNG call count flow-dependent and desynchronises the stream, so a seeded run stops reproducing and `scenario-app-traffic`'s ground truth stops reconciling (`TestFlowJitter_DrawIsUnconditional` guards it; the app-traffic determinism test cannot, since it compares two runs of the same build). **Why jitter at all:** creation is driven by expiry (the cache refills exactly what it lost) and expiry was a deterministic offset from creation, so the creation profile was a pure delay of itself and any irregularity echoed every lifetime forever. Measured autocorrelation at one lifetime fell from +0.96 (GPU) / +0.87 (edge) to +0.17 / +0.23; `TestFlowEmission_EchoIsDamped` asserts it **relative to an undamped baseline it computes itself** via `FlowCache.activeJitterFraction`, not against a threshold, because profiles differ in how much echo they start with (campus is +0.54 undamped, its `DurationMax` sitting on the active timeout so most flows already leave by the self-damping inactive branch).

**The jitter exposed a pre-existing pacing error, and that fix is the load-bearing half.** `effectiveFlowLifetime(fe, sweep)` = `MeanFlowLifetime + sweep/2`: expiry is noticed by a periodic sweep, so a flow's real residency includes the mean wait for it. `flowPacingTarget` / `flowRateReachable` now take the sweep and divide by residency; `installScenPart` passes the SCENARIO's cadence (`scenarioFlowTickInterval`), not the fleet's, because that is what will actually drain the device. Two consequences: the documented per-device ceiling moved 8.5-9.7 → **8.1-9.2 records/s**, and paced runs stopped emitting a few percent low (nl6#462). The term was invisible before the jitter because deterministic deadlines on flows created at sweep boundaries expired at sweep boundaries, so the sweep cost exactly zero. That alignment was an artifact of synthetic timing, not a property of the exporter. **Do not fold the sweep term into `MeanFlowLifetime`** — that is a property of the profile and timeouts, while the sweep is a property of the exporter's cadence, and a scenario may sweep at a different cadence from the fleet.

**Trap operational notes:**
- **`maxTrapPDU` is a FRAME bound, derived, not a literal (nl6#487).** It is `linkMTU - ipv4HeaderBytes - udpHeaderBytes` (1472 at the default MTU), registered in `recomputeDatagramBudgets()` so it tracks `-datagram-mtu`. It was previously a literal 1500 justified as "matches the buffer the legacy path allocated" — the same payload-versus-frame conflation as nl6#485, which put a full-size trap at 1528 B on the wire. **Wire-verified:** an entry sized between the two bounds fragments 40/40 datagrams under the old bound and is refused under the new one. No address-family branch (unlike flow), because trap collectors resolve `udp4` only. Three sites read it and must stay in agreement: the `trapBufPool` allocation, the reference-encoder scratch clamp (both `trap_exporter.go`), and the encode guard (`trap_encode_fast.go`).
- **Two size enforcement points; the load-time one DISABLES rather than rejects.** Catalog load dry-renders each entry (worst-case context INCLUDING a worst-case `{{.Detail}}` and a max request ID — rendering `Detail` empty let a Raise entry pass load and fail at every fire while its Clear was disabled, which can strand an alarm) and marks anything over budget `oversized`: it stays in the catalog but is excluded from BOTH `Pick` and `EntriesByRole`, and is named once at startup. Filtering only `Pick` would leave an oversized `linkDown` firing on every oper-status transition. Loading does NOT fail, because the budget follows an operator-settable MTU — rejecting would make any `-datagram-mtu` below ~1004 refuse to boot on nl6's own shipped optical catalogs, which the operator can fix from neither side. The fire-time encode guard remains the backstop for runtime `{{.Detail}}` and REST `varbindOverrides`, which a load-time render cannot bound.
- **Lowering `-datagram-mtu` disables shipped optical trap entries.** The Ciena `opticalPreFecS[DF]{Raise,Clear}` alarms carry 39 varbinds and encode to 989-1000 B once `{{.Detail}}` and a worst-case request ID are accounted for, so below roughly MTU 1028 they stop firing and are named in the startup log with the size, the gap, and the MTU that would admit them. If optical alarms go quiet after an MTU change, that log line is the answer.
- `TrapSubsystemConfig.PDUBudget` is **required** and passed explicitly by the caller after `SetLinkMTU` has run; a non-positive value is rejected rather than defaulted. The loader does not read the global, so a size check cannot silently run against the default MTU if startup order changes.
- The fire-path resolve/encode error log is `sync.Once`-gated per exporter (`logFirstEncodeErr`), matching `firstWriteErr`. Ungated it was ~1,000 lines/second at 30k devices for a defect present since startup. `sendFailures` still counts every occurrence — only the log line is suppressed.
- INFORM mode (`-trap-mode inform`) requires `-trap-source-per-device=true` (the default) so the per-device UDP socket can demux acks without a global request-id table. Enforced at device-attach time (phase 4 moved it out of startup).
- Pending-inform map is bounded at 100 per device with oldest-drop overflow policy (exposed as `informsDropped` in `GET /api/v1/traps/status`).
- Retransmissions consume global-cap tokens (design decision to prevent retry-storm amplification when the collector is unreachable).
- Collector-side `rp_filter` may need relaxing (`net.ipv4.conf.*.rp_filter=0` or `2`) to accept UDP/162 with 10.42.0.0/16 source IPs — same caveat already documented for flow export.
- Per-device UDP source binding reuses the same `setupVethPair` + `FORWARD -i veth-sim-host -j ACCEPT` iptables rule that flow export already relies on. No new netns / iptables surface.
- **`StopTrapExport` is shutdown-only** (phase-5 review D1). It is not safe to race concurrent device creation: `startDeviceTrapExporter` captures scheduler / pool / encoder pointers under a short RLock and uses them outside that lock, so a concurrent Stop can leave orphan exporters or closed sockets. Today it is only called from the process-exit signal handler. Do not introduce a runtime "restart trap subsystem" control path without first tightening the attach-path lock discipline.

With vendor-wins-per-role, a `cisco_ios` port-down fires both `%LINK-3-UPDOWN` and `%LINEPROTO-5-UPDOWN` (and NOT the generic `interface-down`); `juniper_mx240` fires `SNMP_TRAP_LINK_DOWN`/`_UP`.

- **Unified template vocabulary (11 fields, same set as trap):** `{{.DeviceIP}}`, `{{.SysName}}`, `{{.IfIndex}}`, `{{.IfName}}`, `{{.Now}}`, `{{.Uptime}}`, `{{.Model}}`, `{{.Serial}}`, `{{.ChassisID}}`. - SD-NAME keys are validated against RFC 5424 §6.3.3 at load; each templated value is pre-compiled to a `*template.Template` so the fire hot path is allocation-light (measured 894 ns/op).
- Entry `appName` is required (RFC 3164 TAG has no NILVALUE). Facility and severity accept canonical names (`local7`, `error`) or integers in range (`0..23` / `0..7`). MTU-safety dry-render rejects entries whose worst-case rendered output exceeds 1400 bytes.

**Syslog catalog JSON schema** (one entry; the file is `{"entries":[…]}`):

```json
{
  "name":     "interface-down",       // required; unique within catalog
  "weight":   40,                     // weighted-random Pick; 0/omitted → 1
  "facility": "local7",               // name (kern/user/.../local0..local7) or integer 0..23
  "severity": "error",                // name (emerg/alert/crit/err|error/warning|warn/notice/info/debug) or integer 0..7
  "appName":  "IFMGR",                // required (3164 TAG has no NILVALUE); sanitised to ASCII token
  "msgId":    "LINKDOWN",             // 5424 MSGID; empty → NILVALUE; dropped in 3164
  "hostname": "{{.SysName}}",         // optional override; empty → sysName→DeviceIP fallback
  "structuredData": {                 // 5424 STRUCTURED-DATA; empty map → NILVALUE; dropped in 3164
    "ifIndex": "{{.IfIndex}}",        // keys must match RFC 5424 §6.3.3 SD-NAME grammar
    "ifName":  "{{.IfName}}"
  },
  "template": "Interface {{.IfName}} (ifIndex={{.IfIndex}}) changed state to down"
}
```

**HOSTNAME derivation priority** (resolved at fire time, per design §D5):
1. If the catalog entry defines a non-empty `hostname` template, render it (with the six-field vocabulary) and use the result.
2. Otherwise, use the device's stored `sysName.0` value (captured at device construction).
3. Otherwise, use the device's IPv4 as dotted-quad.

In every branch the result is run through `sanitiseHostname`: spaces become hyphens (spec mandate), other framing / control chars become `_`.

**Syslog transport seam (`add-syslog-tcp`, nl6#92):** `SyslogTransport` (`syslog_transport.go`) sits UNDER the write; catalog resolution, template vocabulary, the scenario gate and ledger accounting stay above it and are transport-independent. `udpTransport` is the datagram path byte-for-byte (including the per-device-bind → shared-pool ladder); `tcpTransport` (`syslog_transport_tcp.go`) is RFC 6587. Same shape as `DialoutTransport`. **TCP is deliberately NOT symmetric with UDP:** it has no shared-socket rung, because one connection carrying several devices multiplexes them into a framed stream with no field to demultiplex on — so a failed connection refuses the attach, and `-syslog-source-per-device=false` makes a TCP attach FAIL rather than degrade. Three things are load-bearing and non-obvious: (1) `SO_SNDBUF` is capped at 16 KiB because Linux auto-tunes to ~4 MiB per connection and this opens one per device (~117 GiB at 30k devices); (2) every write carries a deadline, because the syslog scheduler fires INLINE for the whole fleet so one stalled collector would stop every device; (3) only a read ERROR counts as connection loss — a collector banner would otherwise cause a permanent connect/drop loop. `sent` means "handed to the kernel" on TCP, not "on the wire"; status rows carry `transport` so TCP and UDP devices do not merge. **`maxSyslogMessageBytes = 1400` is a DATAGRAM bound that applies to every catalog regardless of transport** — deliberately, since the check is a once-per-entry dry render at load and making it transport-aware would defer it to a per-device runtime failure.

**Syslog TLS (`add-syslog-tls`, nl6#93):** there is NO `tlsTransport` type — RFC 5425 IS RFC 6587 inside a TLS session, so TLS decorates the DIALER (`syslog_transport_tls.go`) and `tcpTransport` is reused whole. **nl6 is the CLIENT: it verifies the COLLECTOR (`tls.ca_pem` INLINE / system roots / explicit `insecure_skip_verify`) and presents no cert.** The CA is inline PEM, not a path, because the per-device config is REST-settable and a path there is an arbitrary-file-read primitive (CodeQL `go/path-injection`); a path survives only as `-syslog-tls-ca`, read once at startup by `loadSyslogTLSCAFile`. The issue asked which cert to present — that misreads the direction; `sharedTLSCert` is a SERVER identity and is relevant only under mTLS, which is rejected until implemented. **The trap to know:** `dialOnce` caps `SO_SNDBUF` and sets keepalives via `c.(*net.TCPConn)`, which a `*tls.Conn` does not satisfy — so the TLS dialer calls `applySyslogTCPSocketOptions` on the raw socket BEFORE wrapping. Skip that and every TLS device silently inherits Linux's ~4 MiB auto-tuned buffer (~117 GiB at 30k devices). Port defaults to 6514 vs 514, so a bare hostname changes port when the transport changes. TLS record buffers are per connection and ADDITIONAL to the socket buffer, so the plaintext fleet-memory figure does not carry over.

**Syslog operational notes:**
- The format is per-device post-phase-5 — each device's `syslogConfig.Format` sets its own wire format. The shared-socket pool is keyed by `(collector, format)` so 5424 and 3164 streams never interleave on the same socket.
- Per-device UDP source binding reuses the same `setupVethPair` + `FORWARD -i veth-sim-host -j ACCEPT` rule shared by flow / trap. No new netns / iptables surface.
- Per-device bind failure is **non-fatal** for syslog (unlike INFORM): exporter logs a warning and falls back to the shared socket. When the primary per-device write fails but the shared fallback succeeds, the primary failure is logged and stats count the send as successful. If **both** per-device bind and shared-pool open fail, the attach is rejected so `ListDevices` doesn't show a ghost entry.
- The collector-side `rp_filter` caveat is the same as flow / trap — accept UDP from device IPs with `net.ipv4.conf.*.rp_filter=0` or `2`.
- On-demand HTTP fires **bypass the global rate limiter** (test-harness use case; scheduler-driven traffic still honours `-syslog-global-cap`).
- **`StopSyslogExport` is shutdown-only** (phase-5 review D1). Same constraint as trap: `startDeviceSyslogExporter` uses captured pointers outside the short RLock. Only called from the process-exit path today. Tightening is a pre-requisite for any runtime "restart" control plane.

### Key design decisions

- **sync.Map for OID lookups** — lock-free O(1) access during concurrent SNMP queries
- **Pre-computed next-OID mappings** — efficient SNMP GETNEXT/WALK without scanning
- **Buffer pool** — reduces GC pressure on SNMP request handling
- **Shared SSH/TLS keys** across all devices — avoids per-device key generation overhead
- **Network namespace isolation** (`nl6sim` namespace) — prevents systemd-networkd interference
- **Per-device flow egress** — `setupVethPair` installs a `FORWARD -i veth-sim-host -j ACCEPT` iptables rule so that per-device flow exporters can send UDP out of the ns through the host's routing table (Docker-present hosts default FORWARD to drop). Rule is removed in `NetNamespace.Close`. The simulator image includes `iptables` for this reason. On the downstream flow collector, `rp_filter` may need to be relaxed (`net.ipv4.conf.*.rp_filter=0` or `2`) to accept packets with 10.42.0.0/16 source IPs.

### Device types

29 device types across 9 categories: Core Routers, Edge Routers, Data Center Switches, Campus Switches, Firewalls, Servers, GPU Servers (NVIDIA DGX-A100/H100/HGX-H200), Storage Systems (AWS S3, Pure Storage, NetApp ONTAP, Dell EMC Unity), Optical Transport (Ciena Waveserver 5).

**Optical value engine (`optical_cycler.go`):** `OpticalCycler.GetDynamicAt(component, leaf, t)` is the single dispatcher for every coherent-optical leaf, keyed by **OCH component name** (never `ifIndex`). Same contract as `IfCounterCycler`: pure function of elapsed time, no per-channel goroutine, immutable after publish, single-init panic guard, per-channel jitter over a **sorted** channel slice (seed salt `^0x4F43_0000`). **Two independent dials** — received power `pIn` and accumulated noise `nAse`, with `osnr = pIn − nAse` in dB — because a single power dial makes OSNR perfectly correlated with power and leaves the *attenuation* (low power / normal OSNR) and *ASE* (normal power / low OSNR) quadrants unreachable. Cascade: `osnr → q-value → pre-fec-ber` (`½·erfc`, monotonic — the erfc tail is **shallow** at the 2e-2 SD-FEC threshold, ~3× per 2 dB, so decade-scale assertions there are wrong physics) `→ fec-uncorrectable-blocks`. Off-spine leaves (`output-power`, `target-output-power`, `laser-bias-current`, `chromatic-dispersion`, `polarization-mode-dispersion`, `polarization-dependent-loss`, `frequency`, `operational-mode`, `line-port`) read none of the receive dials — that flatness *is* the fibre-vs-transponder diagnostic. Both dials share a period so their difference collapses exactly to one sinusoid, making the above-threshold integral behind the block counter closed-form, O(1) and monotonic by construction. Types come from the **pinned OpenConfig revision** (terminal-device 2026-01-14 + platform-transceiver 2026-03-25), which governs over Ciena's native model: statistics leaves at `fraction-digits 2`, `pre-fec-ber` at `fraction-digits 18`, `fec-uncorrectable-blocks` a bare `uint64` counter with **no** stats container. **`post-fec-ber` is not served** — OpenConfig defines it but Ciena removed it, so a collector rule keyed on it would never fire against real hardware. `-optical-scenario` / per-device `optical_scenario` selects the health band via `opticalBandFor`; only `failing` crosses the FEC threshold. **Band boundaries are sized against the jitter envelope, not the nominal point:** each dial mean is jittered ±`opticalMeanJitterDB`, so the OSNR mean — their *difference* — spreads over ±2× that, stacked on top of the OSNR sine amplitude (≤ `1.1×(pInAmp+nAseAmp)` in antiphase). The tier contracts (`degraded` never accrues uncorrectable blocks, `failing` always does) must hold for every channel of every seed, so changing any mean, amplitude, or the jitter constant invalidates the arithmetic documented at `opticalBandFor` — `TestOpticalBandContractsHoldAcrossSeeds` sweeps seeds because a single-seed test passes while a fleet-sized share of channels violates the contract. **Capability symmetry with flow:** a non-clean `optical_scenario` on a type with no OCH inventory is rejected **400** (`opticalIncapableRequest`, the inverse mirror of `flowIncapableRequest`), and `opticalScenarioFieldFor` omits the field from `GET /api/v1/devices` for non-optical types rather than reporting a knob that does nothing.

**On-demand optical degradation (`optical_degrade.go`, `optical_api.go`):** `POST /api/v1/devices/{ip}/optical/{component}/degrade` with `input_power_drop_db` / `noise_rise_db` / optional `duration` (24h cap; neither offset = clear). Two knobs, not one severity dial — they select the diagnostic quadrant (attenuation: power down, **OSNR unchanged** — the sag hits `pInAt` AND `nAseAt`, because signal and accumulated ASE traverse the same fibre, so it cancels out of `osnr = pIn − nAse`; ASE: power held, OSNR down). Crossing the FEC threshold therefore requires `noise_rise_db`, which is the discrimination collector rules key on and the reason the engine has two dials. **Degradation is an append-only list of immutable `opticalEpisode`s** (`atomic.Pointer[[]opticalEpisode]` per channel, copy-on-append), NOT an install-and-clear pointer: `fec-uncorrectable-blocks` is the time integral of an above-threshold indicator over `[0,t]`, so clearing a "current sag" would remove already-elapsed degradation from the integral and make the counter **decrease** — a collector reads that as a device reboot. Two load-bearing invariants: a published episode's window is frozen (past segments can never change → monotonic by construction), and `t0` is never in the past (no already-observable value is rewritten; a backdated request clamps forward). The one permitted mutation is truncating an *open* episode's end forward to `now` when a later POST supersedes it. `aboveThresholdSeconds` is therefore **piecewise**: the OSNR mean steps at episode boundaries, so the interval splits there and the same closed-form arcsine applies per segment (cost O(boundaries), not O(t); an undegraded channel takes the original single-segment path). The sag is applied in `pInAt`, `nAseAt` **and `osnrAt`** — `osnrAt` reads the precomputed phasor, so sagging `pInAt` alone would move the input-power leaf while leaving the whole cascade untouched. **No revert timer** (deviation from the story's letter, contract preserved): an episode carries its own end and the engine is a pure function of `t`, so the revert is arithmetic — nothing to schedule, cancel, or leak, unlike the interface-state convention which must put mutated state back.

**gNMI decimal values:** `resolvedUpdate.Value` gained `gnmiDecimal{val, digits}` — a distinct type, not a pre-formatted string, because JSON_IETF needs an RFC 7951 quoted decimal while PROTO needs `double_val`; a Go `string` would silently take the `string_val` branch and corrupt an advertised encoding. At 18 fraction digits `double_val` is lossy (inherent to decimal64 in gNMI's PROTO scalar set); JSON_IETF preserves the digits.

**Per-device-type protocol capability.** Device types are not uniformly capable. `ciena_waveserver5` is a layer-1 coherent optical transport platform: it performs no L3/L4 inspection and therefore **exports no flow records**. Absence has to be *implemented*, not omitted — `GetFlowProfile` (`flow_profiles.go`) falls back to `flowProfileEdgeRouter` for any type absent from `flowProfileMap`, so leaving a type out would silently give it edge-router flow ground truth. The explicit marker is `flowIncapableTypes` + `SupportsFlowExport`, consulted at both device-creation paths; a batch-wide flow seed **skips** incapable devices with a log line (so `-flow-collector` stays usable with `-round-robin`), while a request whose entire resolved type set is incapable is rejected with **400** (`flowIncapableRequest`). Its optical inventory is keyed by OCH **component name** (`OCH-1-1`) in an `optical` resource part, never by `ifIndex`; `validateOpticalInventory` fails the load loudly if that part is missing, malformed, or disagrees with `OpticalProfile.ChannelCount`, because the resource decoder is not strict and would otherwise discard it silently.

**Capability-gating boundary (#364):** GROUND-TRUTH-BEARING surfaces — things a collector validates against (flow byte math, optical values) — get per-type fidelity gating (`flowIncapableTypes`, `opticalIncapableRequest`). TRANSPORT PLUMBING deliberately does not: gNMI dial-out is Arista-flavored `gnmireverse` on a fleet with zero Arista types, because its purpose is letting teams test a dial-out collector at scale against a heterogeneous fleet — gating it by fidelity would gate it to the empty set. The absence of dial-out gating is a decision, not an omission. Completeness of the flow maps is enforced in CI (`TestFlowCapabilityCompleteness`: every repo type in `flowProfileMap` XOR `flowIncapableTypes`); operator-supplied custom resource files fall back to the edge-router flow profile with a once-per-type log line, since the compiled-in maps are unreachable to them.

Each device type has resource files under `resources/<device-type>/` containing JSON for SNMP OID responses, SSH command responses, and REST API responses.

## Source file headers

This repo is a fork of `saichler/l8opensim`. Header policy depends on whether a source file is **forked** (basename exists in `go/simulator/*.go` upstream) or **new** (created in this fork):

- **Forked files** keep upstream's full Apache 2.0 boilerplate header verbatim. Do not replace, trim, or modify it — Apache 2.0 §4(c) requires the original copyright notice be preserved when redistributing.
- **New files** (every file in `go/nl6/` whose basename has no upstream counterpart) get the canonical SPDX-short header, no exceptions:

  ```go
  /*
   * Copyright <YEAR> Ronny Trommer <ronny@no42.org>
   * SPDX-License-Identifier: Apache-2.0
   */
  ```

  - `<YEAR>` = file's creation year. Do not bump it on every edit.
  - Email in angle brackets (`<…>`), not parens — REUSE/SPDX scanner convention.
  - **No `Created by` line.** Authorship lives in `git log`, not in headers — it goes stale and conflates authorship (factual) with copyright (legal).
  - Header sits at the very top of the file, with one blank line between the closing `*/` and the next non-blank line (`//go:build` directive, `package` clause, or a leading comment block).
